## Running

The solution run and every test project that declares the `BlobTestContainer` fixture need `ERP_TEST_SQL_CONNECTION`, `ERP_TEST_BLOB_EMULATOR_HOST` and a running Azurite ([local development](local-development.md), sections "Configuration and secrets" and "Attachments storage").

```bash
cd backend && dotnet test --solution Dewiride.Erp.slnx --report-trx --coverage --coverage-output-format cobertura
cd backend && dotnet test --project Modules/Platform/SystemInfo/Tests/UnitTests/Dewiride.Erp.Modules.Platform.SystemInfo.UnitTests
node --test "scripts/roadmap/tests/*.test.ts"
node --test "scripts/checks/tests/*.test.ts"     # seed-file conventions, the secret-pattern check, the contributor licence agreement check, the licence policy, the frontend structure and import rules and every other repository check
node --test "scripts/api-client/tests/*.test.ts" # the client generator arguments and the drift comparison
node scripts/api-client/drift.ts                 # the committed client matches what docs/openapi/erp.json generates
cd frontend && pnpm test:unit                    # web, design-system and ESLint-rule unit tests (src/**/*.test.ts in apps/web and packages/ui, eslint/*.test.mjs in packages/config)
cd frontend && pnpm e2e                          # all projects
cd frontend && pnpm e2e --project=chromium       # one project
```

Results land in `backend/artifacts/TestResults/` (TRX + Cobertura) and `frontend/e2e/playwright-report/` (locally); in CI every shard writes a blob report and the `Playwright` job publishes the merged HTML report as the artifact `playwright-report`.

A pull request runs only chromium and mobile-android, so a change to the Playwright harness (`frontend/e2e/fixtures`, `playwright.config.ts`, `e2e.yml`) also runs the full matrix on its branch before it merges (`gh workflow run e2e.yml --ref <branch>`), and the run of `e2e.yml` on `main` after a merge is watched ([ADR-0029](../adr/0029-captures-of-a-page-at-rest-and-the-hydration-marker.md)).

### Reproducing a CI-only failure in WebKit on Linux

The WebKit projects run on Linux in CI, and a runner is slower than a developer machine. The Playwright image runs the same browsers as a server the local test runner connects to, with the processors of a runner's share:

```bash
MSYS_NO_PATHCONV=1 docker run --detach --name erp-pw-linux --rm --init --ipc=host --cpus=2 -p 127.0.0.1:3390:3390 --workdir /home/pwuser --user pwuser mcr.microsoft.com/playwright:v1.63.0-noble /bin/sh -c "npx -y playwright@1.63.0 run-server --port 3390 --host 0.0.0.0"
cd frontend/e2e && PW_TEST_CONNECT_WS_ENDPOINT=ws://127.0.0.1:3390/ PW_TEST_CONNECT_EXPOSE_NETWORK='<loopback>' pnpm exec playwright test <spec> --project=webkit --repeat-each=3 --retries=0
docker stop erp-pw-linux
```

The image tag matches `@playwright/test` in `pnpm-workspace.yaml`, `<loopback>` lets the remote browser reach the servers on `localhost`, and `MSYS_NO_PATHCONV` stops Git Bash rewriting `/home/pwuser`. `--cpus=1` with two workers starves the browser well beyond a runner and `--cpus=2` comes close; every request crosses the connection, so a heavy page such as the kitchen sink loads far more slowly than in CI. A download's `path()` is not available to a remote browser, so the attachments download step fails there.

## Rules

- Names: `Method_Condition_ExpectedResult` for .NET tests, web unit tests (`src/**/*.test.ts`, `packages/config/eslint/*.test.mjs`) and the frontend structure and import tests (`scripts/checks/tests/web-structure.test.ts`, `web-imports.test.ts`, `web-source.test.ts`); sentence-style titles for the other `node --test` files under `scripts/**/tests`. One behaviour per test. No sleeps, no order dependence, no shared mutable state.
- Frontend structure and import boundaries (ADR-0024): every rule of the register in `docs/architecture/dependency-rules.md` has an allowed and a refused case, the script rules (S1–S6, I1–I7) in `scripts/checks/tests/web-{structure,imports}.test.ts` over in-memory file lists (no committed fixture trees, so no other scan sees a violating file) and the ESLint rules (L1–L6, X1–X2) in `frontend/packages/config/eslint/feature-boundaries.test.mjs` through the full presets, so the order of the flat-config objects is tested too. A new or changed rule changes the register, its enforcer and its test table together. No Playwright spec belongs to these rules. The existing specs of sign-in, navigation, system information, attachments and the kitchen sink cover the moved sign-in frame and the not-found content a person sees; the feedback spec reaches the shell's error state and a page's own loading status, and no spec reaches the root `error.tsx` or `global-error.tsx`, which render only when the shell's or the root layout itself, the `(auth)` pages or the sign-in page fail.
- Database under test: a SQL-backed test project declares `[assembly: AssemblyFixture(typeof(SqlTestDatabase))]` once, which creates the per-process database before the first test, migrates it and runs every seeder the way the migrator does, and drops it after the last; a test of the migration path itself uses `EmptyTestDatabase`, a fresh database no migration has touched (`Dewiride.Erp.Host.Migrator.IntegrationTests`); `ErpApiFactory` injects `SqlTestDatabase.Current.ConnectionString` as `Erp:Platform:Database:ConnectionString` into every test host and throws a message naming that `AssemblyFixture` line when no test database exists, so a test host can never reach the developer's own `ErpAiPro` database; `WithConfiguration("Erp:Platform:Database:ConnectionString", ...)` overrides the injection for a test that needs its own database; a test that needs a context outside the host (a migration test, a convention test) takes it from a class fixture built on `SqlTestDatabase.Current`. Every test host reports the readiness checks `self`, `database:files`, `database:platform_idempotency`, `database:platform_system_info` and `storage:attachments`. A test that needs its own endpoints maps them with `ErpApiFactory.WithTestEndpoints(routes => …)`, which runs after the whole request pipeline, so the middleware under test sees them like any module route.
- Blob storage under test: a test project whose tests start API hosts through `ErpApiFactory` also declares `[assembly: AssemblyFixture(typeof(BlobTestContainer))]` (from `Dewiride.Erp.Testing`) next to its `SqlTestDatabase` line.
