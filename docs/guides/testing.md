# Testing

## Layers

| Layer | Where | Tooling | Runs against |
|---|---|---|---|
| Unit | `Modules/<D>/<M>/Tests/UnitTests`, `Tests/BuildingBlocks` | xUnit v3 on Microsoft.Testing.Platform, `FakeTimeProvider`, `FakeLogger<T>` | nothing external |
| Integration | `Modules/<D>/<M>/Tests/IntegrationTests`, `Tests/Host`, `Tests/BuildingBlocks` (SQL-backed projects) | `WebApplicationFactory<Program>` from `Dewiride.Erp.Testing` (`ErpApiFactory`, `ErpApiFactory.ForEnvironment`); the `SqlTestDatabase` and `BlobTestContainer` assembly fixtures | a real SQL Server, the Azurite Blob Storage emulator and no Azure: the `SqlTestDatabase` assembly fixture creates `ErpAiProTest_<yyyyMMddHHmmss>_<8 hex>` per test process from `ERP_TEST_SQL_CONNECTION` (the owner's instance locally, the `start-sql-server` action in CI), migrates every catalogue context and drops the database at the end; the `BlobTestContainer` assembly fixture creates the storage container `erptest-<yyyyMMddHHmmss>-<8 hex>` per test process on the Azurite at `ERP_TEST_BLOB_EMULATOR_HOST` (the owner's `erp-azurite` container locally, the `start-azurite` action in CI), deletes leftover `erptest-` containers older than 24 hours first and its own container at the end; a missing variable fails with a message naming it. Every `ErpApiFactory`, Development or Production, forces the in-memory configuration source (`ERP_CONFIGURATION_SOURCE=InMemory`, `APPCONFIG_ENDPOINT` blanked) so tests never need an endpoint and a developer's user secrets cannot connect a test host to the store; the test authentication handler arrives with the authentication phase |
| Architecture | `Tests/Architecture` | ArchUnitNET; one `ErpApiFactory` host for `ModuleCatalogTests`, `PersistenceTests` and `RequestRecordTests` | compiled assemblies plus the `SqlTestDatabase` per-process database and the `BlobTestContainer` per-process storage container (the project declares both assembly fixtures, so it needs `ERP_TEST_SQL_CONNECTION` and `ERP_TEST_BLOB_EMULATOR_HOST` like the integration projects); its `coverage.settings.xml` excludes every module from coverage instrumentation, because ArchUnitNET reads the assemblies from disk and the static instrumentation the coverage tool uses on Linux rewrites them for the duration of the run |
| Web unit | `frontend/apps/web/src/**/*.test.ts` and `frontend/packages/ui/src/**/*.test.ts`, next to the code | `node --test` on Node 24 (native type stripping, no extra packages), started by `erp-unit-tests`, the bin of `@dewiride/erp-config` (`packages/config/cli/run-unit-tests.mjs`), which runs every `src/**/*.test.ts` of the package and fails when none matches, so an emptied suite cannot pass; `pnpm test:unit` in each package, and from `frontend/` for both; `Method_Condition_ExpectedResult` titles | pure modules only (the environment schema, the forwarded request headers, the problem mapping of `toApiError` and of `problemFromBody` for browser uploads, the byte sizes of `shared/format/sizes.ts`; in `packages/ui` the OKLCH conversion and contrast ratio of `src/lib/oklch.ts`, the contrast gates of `src/styles/contrast.test.ts`, which reads the light and dark tokens from `theme.css` and composites every tint and hover fill over each backdrop a control sits on, and `src/lib/utils.test.ts`, which proves that `tokens/typography.css`, `typeRoles` in `utils.ts` and the ESLint `typeRoles` name the same roles, that the configured `cn` merges the roles as font sizes, and that it merges every `--spacing-*` and `--container-*` name of `tokens/layout.css` and every `--ease-*` name of `tokens/motion.css` with Tailwind's scale); nothing external |
| Scripts | `scripts/roadmap/tests`, `scripts/checks/tests`, `scripts/api-client/tests`, `scripts/ef/tests` | `node --test`; sentence-style titles (`test('a labelled override needs an unlabelled default', ...)`) | the roadmap model in a temp directory; the seed files under `infra/appconfig`; a throwaway git repository for the secret-pattern check; the Azurite image references in `infra/compose/compose.override.yaml`, `.github/actions/start-azurite/action.yml` and `docs/guides/local-development.md` (`azurite-pin.test.ts`: one version-and-digest pin, followed everywhere); the Kiota arguments and the generated-tree comparison; the `dotnet ef` arguments and the context discovery over a temp tree |
| End-to-end | `frontend/e2e` | Playwright | built web app + running API |

## Running

The solution run and every test project that declares the `BlobTestContainer` fixture need `ERP_TEST_SQL_CONNECTION`, `ERP_TEST_BLOB_EMULATOR_HOST` and a running Azurite ([local development](local-development.md), sections "Configuration and secrets" and "Attachments storage").

```bash
cd backend && dotnet test --solution Dewiride.Erp.slnx --report-trx --coverage --coverage-output-format cobertura
cd backend && dotnet test --project Modules/Platform/SystemInfo/Tests/UnitTests/Dewiride.Erp.Modules.Platform.SystemInfo.UnitTests
node --test "scripts/roadmap/tests/*.test.ts"
node --test "scripts/checks/tests/*.test.ts"     # seed-file conventions, the secret-pattern check and every other repository check
node --test "scripts/api-client/tests/*.test.ts" # the client generator arguments and the drift comparison
node scripts/api-client/drift.ts                 # the committed client matches what docs/openapi/erp.json generates
cd frontend && pnpm test:unit                    # web and design-system unit tests (apps/web and packages/ui, src/**/*.test.ts)
cd frontend && pnpm e2e                          # all projects
cd frontend && pnpm e2e --project=chromium       # one project
```

Results land in `backend/artifacts/TestResults/` (TRX + Cobertura) and `frontend/e2e/playwright-report/`.

## Rules

- Names: `Method_Condition_ExpectedResult` for .NET tests and for web unit tests (`src/**/*.test.ts`); sentence-style titles for `node --test` files under `scripts/**/tests`. One behaviour per test. No sleeps, no order dependence, no shared mutable state.
- Database under test: a SQL-backed test project declares `[assembly: AssemblyFixture(typeof(SqlTestDatabase))]` once, which creates the per-process database before the first test, migrates it and runs every seeder the way the migrator does, and drops it after the last; a test of the migration path itself uses `EmptyTestDatabase`, a fresh database no migration has touched (`Dewiride.Erp.Host.Migrator.IntegrationTests`); `ErpApiFactory` injects `SqlTestDatabase.Current.ConnectionString` as `Erp:Platform:Database:ConnectionString` into every test host and throws a message naming that `AssemblyFixture` line when no test database exists, so a test host can never reach the developer's own `ErpAiPro` database; `WithConfiguration("Erp:Platform:Database:ConnectionString", ...)` overrides the injection for a test that needs its own database; a test that needs a context outside the host (a migration test, a convention test) takes it from a class fixture built on `SqlTestDatabase.Current`. Every test host reports the readiness checks `self`, `database:files`, `database:platform_idempotency`, `database:platform_system_info` and `storage:attachments`. A test that needs its own endpoints maps them with `ErpApiFactory.WithTestEndpoints(routes => …)`, which runs after the whole request pipeline, so the middleware under test sees them like any module route.
- Blob storage under test: a test project whose tests start API hosts through `ErpApiFactory` also declares `[assembly: AssemblyFixture(typeof(BlobTestContainer))]` (from `Dewiride.Erp.Testing`) next to its `SqlTestDatabase` line. Before the first test the fixture reads `ERP_TEST_BLOB_EMULATOR_HOST` (`127.0.0.1` locally and in CI), fails with a message naming it when it is missing, deletes `erptest-` containers older than 24 hours (left by a process that was killed) and creates the container `erptest-<yyyyMMddHHmmss>-<8 hex>` on the emulator's built-in development account; it deletes the container after the last test. `ErpApiFactory` points every test host at that container (`Erp:Platform:Attachments:EmulatorHost` and `ContainerName` from `BlobTestContainer.Current`, `BlobServiceUri` blanked), so a storage endpoint in a developer's user secrets never reaches a test, and gives every host the same random encryption key for the whole test process (`test:<32 bytes>`), so content one host stored stays readable, and deduplicable, for every other; a test that sets `ErpApiFactory.AttachmentsEmulatorHostKey` or `AttachmentsBlobServiceUriKey` with `WithConfiguration` gets no injected storage setting at all (the container name then comes from `AttachmentsContainerNameKey` or defaults to `attachments`), one that sets only `AttachmentsContainerNameKey` keeps the test emulator with that container, and one that sets `AttachmentsEncryptionKeyKey` gets no injected key. Without the fixture and without its own storage settings, `ErpApiFactory` throws naming the missing `AssemblyFixture` line. Azurite enforces neither role-based access nor the refusal of account keys, so Entra-only access to the real storage account is proven against the development account, never in tests. In CI `.github/actions/start-azurite` runs the emulator (digest-pinned, in-memory, strict about API versions) for `ci-backend.yml`, whose test step receives `ERP_TEST_BLOB_EMULATOR_HOST`, and for `e2e.yml`, whose two API hosts receive `Erp__Platform__Attachments__EmulatorHost` and an encryption key generated and masked for the run; `docker-build.yml` smoke-tests the compose stack with its own `azurite` service and a generated key file. The fixture builds its `BlobServiceClient` with `AttachmentBlobClients.ServiceVersion` (internal, visible to `Dewiride.Erp.Testing`), so the fixture and the product send the same pinned service version to Azurite.
- Attachments behaviour that depends on timing is made deterministic, never slept on: `UploadConcurrencyTests` sets `Erp:Platform:Attachments:MaxConcurrentUploads` to 1 with `WithConfiguration` and registers `HeldScanner`, an `IAttachmentScanner` whose `StartAsync` signals `Entered` and waits for `Release()`, so one upload is known to be in flight inside the endpoint while the next one is refused with 429; `AttachmentsSweeperTests` call `SweepReservationsAsync` and `PurgeUnusedLinksAsync` directly instead of waiting for `SweepInterval`; `StoredContentTests` damage or delete the stored blob, or store content through one host (`WithConfiguration(ErpApiFactory.AttachmentsEncryptionKeyKey, …)`) and upload or link it through a second host whose key has the same id with other material, an id differing only in case, or another id, to prove that deduplication keeps its own copy and that link creation answers 404. Endpoint metadata (the `platform.attachments.transfer` timeout policy and the `platform.attachments.uploads` rate-limiter policy) is asserted from the endpoint data source in `TransferPoliciesTests`.
- Configuration under test: `ErpApiFactory.WithConfiguration(key, value)` passes the value to the test host as a command-line setting, the highest-priority source in a test host, so it overrides `appsettings.json` and also the values the host reads while it is being built (such as `Erp:Platform:Configuration:*`); call it before the first client or service is requested (it throws afterwards). The factory's own `APPCONFIG_ENDPOINT` and `ERP_CONFIGURATION_SOURCE` settings are applied last, so a test can never re-point the host at the store. `ErpApiFactory.WithFeature(name, enabled)` writes a flag in the Microsoft schema the same way, so a test proves both the enabled and the disabled state of a module without Azure (a later `WithFeature` for the same name wins, mirroring provider order).
- Disabled-module states in Playwright come from a second API and web pair (`E2E_GATED_API_BASE_URL`, `E2E_GATED_BASE_URL`; ports 5081 and 3002 when Playwright starts them) whose API runs with `feature_management__feature_flags__<n>__id` and `__enabled=false` for every flag in `gatedFeatureFlags` (`frontend/e2e/fixtures/targets.ts`: `Erp.Modules.Platform.SystemInfo` as flag 0, `Erp.Modules.Platform.Attachments` as flag 1; `e2e.yml` sets the same pairs); specs that need it `test.skip` when the pair is absent and `test.use({ baseURL })` to target it. The gated API still validates its attachment settings at startup although the module is off, so locally Playwright starts it with `AZURE_TOKEN_CREDENTIALS=AzureCliCredential` (it runs with `--no-launch-profile`) and it reads the endpoint and key from user secrets, and in CI it receives the Azurite host and the generated key like the first API.
- Transport: the in-memory test server has no client address and ignores Kestrel limits, so tests of forwarded headers, body limits and response headers on the wire call `ErpApiFactory.WithKestrel()` (a real listener on port 0) on a factory of their own; never combine it with `WithWebHostBuilder`, which silently falls back to the in-memory server. Request timeouts work on either server; the timeout middleware does nothing while a debugger is attached, so run those tests without one.
- Contract: `OpenApiSnapshotTests` (in `Tests/Host`) fails when the running API differs from `docs/openapi/erp.json`; after an intended API change rewrite the file with `cd backend && ERP_OPENAPI_SNAPSHOT=update dotnet test --project Tests/Host/Dewiride.Erp.Host.Api.IntegrationTests/Dewiride.Erp.Host.Api.IntegrationTests.csproj --filter-class "*OpenApiSnapshotTests"` (or `node scripts/api-client/generate.ts`, which also regenerates the web client) and commit both. `OpenApiSchemaShapeTests` keeps generator-hostile constructs out of the document.
- Playwright starts its own servers on ports 5080, 3000, 3001, 5081 and 3002 unless `E2E_BASE_URL` is set; when another program holds one of those ports, start the five servers on free ports and set `E2E_BASE_URL`, `E2E_API_BASE_URL`, `E2E_OFFLINE_BASE_URL`, `E2E_GATED_BASE_URL` and `E2E_GATED_API_BASE_URL` (the same mode `e2e.yml` uses). Locally both API hosts Playwright starts keep attachments in the development storage account as your `az login` identity, the first with the endpoint and key from the store, the gated one (store-less) with those from user secrets ([local development](local-development.md), section "Attachments storage"); in CI both use Azurite. The attachments specs (`tests/platform/attachments/`) therefore write real, encrypted blobs locally: `files.spec.ts` uploads through the real "Choose a file" chooser (`page.waitForEvent("filechooser")`), lists (ARIA snapshot of the table), downloads (compared byte for byte; the page stays on `/platform/attachments`) and deletes (focus lands on the "Stored files" heading) a PNG whose content is fixed per size and whose name is unique, so repeated runs deduplicate to one stored file per size; it also uploads one file by drag and drop, shows the API's 415 reason in `upload-error` for a file whose bytes are not the declared type, checks the drop zone's refusals (an empty file, a type outside the policy) without any request reaching the API, pages through 21 files it seeds through `POST /api/platform/attachments` (Next and Previous, a page far past the end, the malformed `?page=` values `abc`, `0`, `-2`, `1.5` and `999999999999`; deleted again in `finally`), and on Chromium desktop only refuses a file one byte over the 25 MiB limit before sending it and uploads a 12 MiB file through the web origin of `next start`, whose `experimental.proxyClientMaxBodySize` is `"101mb"` (the image's standalone server keeps the 10 MB default, so the suite runs against `next start`, locally and in `e2e.yml`, never against the compose stack's web container); `files-gated.spec.ts` covers the disabled module inside the shell and `files-unavailable.spec.ts` the page without an API.
- Drag and drop in Playwright: the spec builds the `DataTransfer` inside the page (`page.evaluateHandle`) and raises `dragenter`, `dragover` and `drop` from inside the page with `new DragEvent(type, { bubbles: true, cancelable: true, dataTransfer })` on the drop zone (`AttachmentsPage.dragOver`, `drop`), because WebKit does not deliver drag events raised with `locator.dispatchEvent` to React's delegated listeners; the drag is retried with `expect(...).toPass()` until the drop zone reports `data-dragging="true"`, and only then is the file dropped.
- Console errors: the auto fixture `consoleErrors` (`frontend/e2e/fixtures/test.ts`) fails a test on any `console` error and any uncaught `pageerror`; `test.use({ expectedConsoleError: /pattern/ })` tolerates one expected message in both. The API-refusal test expects the browser's 415 resource log line, and the pagination test expects WebKit's report of a Next.js router prefetch (`?_rsc=`) that a navigation cancels, which WebKit words as an access-control failure (`/\?_rsc=[\w-]+ due to access control checks\.$/`).
- Rate limit locally: without `KnownNetworks` every browser request and every server-side call of the web app reaches the API from loopback, so a local run over five browser projects shares one anonymous partition; the `local-dev` label raises `Erp:Platform:RateLimiting:AnonymousPermitLimit` to 6000 for that reason ([configuration](../configuration.md)). CI runs store-less, one project per job, under the default 600.
- Statutory logic: dated, table-driven `[Theory]` cases from the parameter sets, including the boundary dates on both sides of a change.
- Coverage: at least 80 % line coverage for Domain + Application per module; a pull request never lowers it.
- Every feature ships a Playwright spec that visits every page it adds and clicks every button, menu item, tab, dialog and form control (happy path plus one validation failure), asserts no console errors and takes an ARIA snapshot of key screens.
- Playwright runs every visual test in light and dark theme (`forEachTheme`) on desktop Chromium, Firefox, WebKit and the newest Pixel and iPhone descriptors; behavioural tests that render nothing theme-specific (redirects, header checks, the API smoke) run once, and `tests/smoke/**` runs on Chromium only. Pull requests run Chromium and one mobile project, `main` runs the full matrix. Screenshots are named `<spec>/<name>--<project>--<theme>.png`; under `--repeat-each` the copies after the first append `--repeat<N>` to the name, because the copies of a test run side by side and two of them writing one file fail with `EBUSY` on Windows. A second web instance started without an API (`E2E_OFFLINE_BASE_URL`) covers the unavailable states.
- Screenshots: the `capture(name, target?)` fixture takes a screenshot of the element when a locator is given and of the full page otherwise, both with `animations: "disabled"`, which fast-forwards finite animations and transitions to their end and cancels infinite ones, so a capture never shows a dialog half faded in or the login glow mid-cycle. An element capture hides the sticky elements outside the target while it is taken, so the app header never appears partway down a tall section. Screenshots are gitignored artefacts that CI uploads; no test compares them with a baseline.
- Design system: `tests/platform/design/kitchen-sink.spec.ts` with the page object `pages/platform/design/kitchen-sink.page.ts` covers `/design/kitchen-sink` on every project.
  - Setup: `KitchenSinkPage.goto()` waits for the heading and then for the motion demo's `data-reduced-motion` attribute, which only the browser sets, so no pointer or key reaches the page before React has hydrated it (a hover before hydration opens nothing). The long tests are split by section group, and a `test.beforeEach` calls `test.slow(browserName === "webkit", …)`, which triples the timeout of every test in the file on the WebKit projects (`webkit`, `mobile-ios`) only; "triples the timeout on WebKit only" asserts `test.info().timeout` against the project timeout on every project. The modifier is not a describe-level `test.slow(({ browserName }) => …)`: a modifier callback that takes only worker fixtures runs as a `beforeAll` modifier, which triples the hook's time slot and leaves every test's timeout unchanged.
  - Tokens, in each theme: the document title, the `dark` class and `color-scheme` of `<html>` and the `<meta name="color-scheme" content="light dark">`; that every colour custom property the stylesheets define on `:root` (read from `document.styleSheets` and recognised with `CSS.supports("color", value)`, because the production build rewrites `oklch()` into hex and `lab()`; the elevation colours excluded) has exactly one swatch and each computed fill is not transparent; that the typography roles compute their size, line height, weight and letter spacing; the 14 spacing and 8 radius specimens and a shadow on every shadow step; the 16 px phone and 24 px `sm` page gutter; the header on layer 40; the rows of the layer (4) and motion (7) tables; an ARIA snapshot of the section index and of the Focus section; and, after tabbing onto the Focus section's link, a solid 2 px outline offset 2 px in the computed `--ring` colour (`focus-ring-keyboard`). WebKit leaves links out of the Tab order unless Safari's "Press Tab to highlight each item" is on, so there `tabOntoLink` focuses the link from script right after a key press, which `:focus-visible` treats as keyboard focus.
  - Primitives, in each theme: the disabled, invalid, busy and indeterminate states; the loading button's name, exactly "Saving"; the range slider's description; the excluded table's caption, column headers, 15 rows and deciding roadmap items; ARIA snapshots of the input, selection, navigation and data-display sections (the item list with its list items, the accordion headings at level 4); keyboard focus captures and, on desktop, a hover capture. The two tests capture every token and primitive section, and the full page on desktop only, because a full-page capture of the 3× mobile device exceeds the 16 384-pixel limit Chromium paints.
  - Overlays: every dialog, confirmation, sheet, popover, hover card and tooltip is opened (an ARIA snapshot and a capture of each; Escape closes each, and focus returns to the trigger of a dialog, confirmation, sheet or popover; hover cards and tooltips open on hover on desktop and on focus on mobile) and each action inside it is used.
  - Menus: the dropdown, context and menu-bar menus choose every enabled plain and checkbox item and at least one radio item per group (all three View zoom levels), open every submenu and choose its items, check and re-read each checkbox and radio choice, and choose one destructive item per menu type ("Delete draft", "Remove", "Clear lines"), asserting `data-variant="destructive"` and that the menu closes. The navigation menu follows all seven of its links to their hash, and on a touch device it is tapped before anything on the page is clicked: a mouse click leaves a pointer position behind, and after a scroll the browser reports that pointer leaving the menu, which starts Radix's close timer, and a tap does not cancel it; the menu bar therefore runs in a test of its own. "reaches the context menu area and the menu bar with the keyboard" tabs from "Invoice actions" to the context-menu area (a solid 2 px outline) and on to "File", presses ArrowRight to "Edit" (the focused trigger alone has a `box-shadow`), opens it with Enter and closes it with Escape; "opens the context menu with the context-menu key" presses Shift+F10 and the ContextMenu key on the focused area on Chromium only, because Firefox and WebKit do not turn a key press Playwright sends into a `contextmenu` event.
  - Controls: every button of the action specimens, the toggles and toggle groups, every editable text field (the invalid GSTIN, the credit-note textarea, the discount and client-search input groups included), both native selects and both Radix selects, the enabled checkboxes, radios and switches of the input and selection sections (the small and the invalid switch included), both slider thumbs with the arrow keys (the description then reads "From ₹25,000 to ₹75,000."), every enabled tab (and the focus ring of the panel of each tab list), the breadcrumb and pagination links, the card, item, accordion, collapsible, scroll-area and empty-state controls, the example form empty (the field error and `aria-invalid`, the validation failure) and valid (a toast), every toast, the drop zone with an accepted file, a file of the wrong type and a file over the limit through the file chooser, and the theme toggle.
  - Once, outside the theme loop: "section index links reach their sections" follows every index link and checks that the section heading is in view and not under the header; "keeps keyboard focus clear of the sticky header" checks that `scroll-padding-top` of `<html>` equals the header's height and that 12 Shift+Tab stops back from "Edit contact" each end below the header; "keeps every table and menu inside the screen" runs at 320 × 720 and checks that the page and its 4 tables do not overflow and that every dropdown, context and menu-bar menu and submenu stays inside the screen (edges rounded to whole pixels, because Radix rounds a menu's position to device pixels while its width stays fractional).
  - A new token or primitive on the page extends this spec in the same change.
- Radio groups by keyboard: Radix moves roving focus to the next radio in a timeout and checks it only while the arrow key is still down, so `keyboard.press` moves focus without checking; `pressArrowUntilChecked(page, key, radio)` from `fixtures/test.ts` holds the key until the radio is checked. `tests/shared/layout/theme-toggle.spec.ts` enters the theme toggle with Tab, moves through light, dark and system with each of the four arrow keys (Right and Down to the next theme, Left and Up to the previous), checks the 2 px focus outline and that Tab leaves the group in one stop; "outlines the chosen theme when the system forces colours" sets `page.emulateMedia({ forcedColors: "active" })`, asserts that `(forced-colors: active)` matches, and checks that the chosen item has a solid 2 px outline and the other two none (WebKit's emulation switches the media query without forcing the colours, which is enough for this check).
- Reduced motion: the kitchen-sink spec's `motion` tests run once, outside the theme loop. Without the preference the motion demo reports it off, `--motion-duration-slow` reads `300ms` and the demo's `animate-fade-up` element runs 0.3 s. With `page.emulateMedia({ reducedMotion: "reduce" })` set before navigation, the demo reports it on, the duration tokens read `0.01ms`, and the computed `animation-duration` of the demo animation, the `transition-duration` of the token-driven transition and the animation of an open dialog's overlay (the generated literal `duration-100`, reached only by the global safety net) are each at most 0.01 ms, and the glow on `/login` runs a single iteration.
- Tests obey the same comment and package rules as production code.
