# Routing register

Every API route group and web route in the system. API routes follow `/api/<domain>/<module>/<resource>`; web routes mirror them without the `/api` prefix. Exempt prefixes: `/api/auth/*`, `/api/platform/*`, `/healthz/*`.

Every API response carries `X-Correlation-ID`, and every non-2xx body is `application/problem+json` with `type` (`/problems/<code>`), `code`, `status`, `title`, `instance` and `traceId` (the correlation id); validation problems add `errors`. Every module route also documents 400 (validation), 404 (unknown resource or disabled module), 429 (rate limit), 500 and 504 (timeout). Any route except `/healthz/*` may answer 429 `rate-limit.exceeded` with `Retry-After` (anonymous callers are counted per client address, signed-in callers per actor; `Erp:Platform:RateLimiting`; the attachments upload also answers it when `Erp:Platform:Attachments:MaxConcurrentUploads` uploads are already in flight). Any route may also answer 400 `request.host-not-allowed` (a `Host` outside `Erp:Platform:Host:AllowedHosts`), 413 `request.too-large` (a body over `Erp:Platform:Host:MaxRequestBodyBytes`, or for the attachments upload over `Erp:Platform:Attachments:MaxSizeBytes` plus 64 KiB) and 504 `request.timeout` (a request running past `Erp:Platform:Host:RequestTimeout`); see [request pipeline](architecture/request-pipeline.md). The committed contract of these routes is [`docs/openapi/erp.json`](openapi/erp.json); the rules are in [HTTP conventions](architecture/http-conventions.md).

## Host endpoints

| Route | Auth | Purpose |
|---|---|---|
| `GET /healthz/live` | anonymous | process liveness (container health check); runs no check; never rate limited and left out of request metrics |
| `GET /healthz/ready` | anonymous | readiness including dependencies (`self`, `database:<schema>` per catalogue context, `storage:attachments`, which only degrades, and `app-configuration` with the App Configuration source, which only degrades), each check limited to 2 seconds: `200 text/plain` `Healthy` or `Degraded`, or `503 application/problem+json` `service.unavailable` naming no check; never rate limited and left out of request metrics |
| `GET /openapi/erp.json` | anonymous, Development only | OpenAPI 3.1 document, identical to the committed [`docs/openapi/erp.json`](openapi/erp.json) apart from formatting |
| `GET /scalar` | anonymous, Development only | API reference UI |
| `GET /api/platform/features` | anonymous until the authentication phase | every feature flag of the catalog with its evaluated state (`{ features: [{ name, enabled }] }`), read by the web shell to hide disabled modules |

Two conventions apply to the routes this register lists, from the module that first uses them: a route that creates something carries `.RequireIdempotencyKey()`, so the caller sends an `Idempotency-Key` header with a UUID, a repeat of the same request replays the first response with `Idempotency-Replayed: true`, and the same key with a different body answers 422; a route that lists something accepts `?page=&pageSize=&sort=&filter=` with per-route field allow-lists. Both grammars are in `docs/architecture/application-pipeline.md`. `system-info/startups` predates the paging convention and takes `?take=` instead; `GET /api/platform/attachments` is the first paged route. The two attachment routes that create something, the upload and `download-links`, deliberately carry no idempotency key (ADR-0022): the middleware would buffer a whole upload before the endpoint runs, and would store a download link's token in plain text, while repeating either request is harmless.

## Modules

| Domain / Module | API group | Web routes | Notes |
|---|---|---|---|
| Platform / SystemInfo | `GET /api/platform/system-info`, `GET /api/platform/system-info/startups` | `/platform/system-info` | anonymous until the authentication phase; then requires an authenticated user; gated by `Erp.Modules.Platform.SystemInfo`. `startups` (route name `Platform.SystemInfo.ListStartups`) takes `?take=` (1 to 100, default 20; outside the range 400 `request.invalid` with `errors.take`, not a number 400 `request.malformed`) and answers `200 application/json` `{ startups: [{ id, applicationName, version, framework, environmentName, configurationLabel (nullable), startedAt, recordedAt }] }`: the most recent starts of the API, newest first (`startedAt` then `recordedAt` descending, ISO 8601 UTC); `MachineName` is stored and never returned while the route is anonymous. The web page shows the identity card and the recent-starts table |
| Platform / Attachments | `GET /api/platform/attachments`, `GET /api/platform/attachments/policy`, `POST /api/platform/attachments`, `GET /api/platform/attachments/{id}`, `DELETE /api/platform/attachments/{id}`, `POST /api/platform/attachments/{id}/download-links`, `GET /api/platform/attachments/{id}/content?link=` | `/platform/attachments` (`?page=`) | anonymous until the authentication phase, which enforces the module's permissions `platform.attachments.files.upload`, `platform.attachments.files.read` and `platform.attachments.files.delete` (`AttachmentsPermissions`); gated by `Erp.Modules.Platform.Attachments`; `{id}` carries the `guid` route constraint, so a malformed id matches no route and answers 404. Until authentication every caller is the anonymous actor, so links are not yet separated per person. Routes and route names (table below); the flows are in [attachments](architecture/attachments.md). The web page lists attachments 20 per page with `?page=`: `readPageParameter` (`frontend/apps/web/src/shared/api/paging.ts`) accepts only an ASCII whole number from 1 to `lastRequestablePage(20)` = 107 374 183 (the last page the API's `PageRequest` accepts for that page size), and anything else redirects to `/platform/attachments`; a page past the last redirects to the last page, or to `/platform/attachments` when the list has at most one page. The upload policy and the list load independently, so each card shows its own failure. The page uploads through the shared drop zone with progress (refusing a file over the policy's size or of another type before sending it, and showing the API's reason for a refusal), downloads through a fresh link opened by a temporary same-origin `<a download>`, so the page stays put and a link that cannot be created shows in the row, and deletes after a confirmation dialog, moving focus to the "Stored files" heading |

Platform / Attachments routes (every attachment is `{ id, fileName, contentType, sizeBytes, sha256, scanStatus ("notScanned" or "clean"), createdAt, createdBy }`):

| Route | Name | Answers |
|---|---|---|
| `GET /api/platform/attachments` | `Platform.Attachments.List` | `200` `{ items, page, pageSize, totalCount, totalPages }`, newest first unless sorted; `page`, `pageSize` (1 to 200, default 50), `sort` over `fileName`, `contentType`, `sizeBytes`, `createdAt`, `filter` over `fileName`, `contentType`, `createdAt`; 400 `query.*` |
| `GET /api/platform/attachments/policy` | `Platform.Attachments.GetUploadPolicy` | `200` `{ maxSizeBytes, allowedContentTypes }` (types sorted) |
| `POST /api/platform/attachments` | `Platform.Attachments.Upload` | `multipart/form-data`, the first part with a file name is the file, and that name must end in an extension of the declared type; body limit `MaxSizeBytes` + 64 KiB, timeout policy `platform.attachments.transfer` and rate-limiter policy `platform.attachments.uploads` (at most `MaxConcurrentUploads` uploads in flight per API process); no `Idempotency-Key`. `201` with `Location: /api/platform/attachments/{id}` and the attachment; 400 `attachment.file-missing`, `attachment.file-name-invalid`, `attachment.empty`, `attachment.incomplete`; 413 `attachment.too-large` or `request.too-large`; 415 `attachment.multipart-required`, `attachment.unsupported-type`, `attachment.extension-mismatch`, `attachment.content-mismatch` (leading bytes, or text that is not UTF-8 without NUL anywhere in the file); 422 `attachment.infected`; 429 `rate-limit.exceeded` with `Retry-After` when the concurrency cap is reached |
| `GET /api/platform/attachments/{id}` | `Platform.Attachments.Get` | `200` the attachment; 404 `attachment.not-found` (unknown or deleted) |
| `DELETE /api/platform/attachments/{id}` | `Platform.Attachments.Delete` | `204`; the attachment is soft-deleted and its links stop working; 404 `attachment.not-found` |
| `POST /api/platform/attachments/{id}/download-links` | `Platform.Attachments.CreateDownloadLink` | `200` `{ url, expiresAt }`, `url` = `/api/platform/attachments/{id}/content?link=<token>` for the person asking, valid for `DownloadLinkLifetime`; no body, no `Idempotency-Key`; 404 `attachment.not-found` when the attachment is unknown or deleted, or its stored content cannot be opened (blob missing, key not configured); a link that expired more than an hour ago unredeemed is deleted by the sweeper |
| `GET /api/platform/attachments/{id}/content?link=` | `Platform.Attachments.Download` | request record `RedeemDownloadLinkRequest`, command `RedeemDownloadLinkCommand`; `200` with the original bytes, `Content-Type` the stored content type (the document declares `application/octet-stream`), `Content-Disposition: attachment` with the stored file name and `Content-Length`; timeout policy `platform.attachments.transfer`; each download recorded; a wrong, expired, other person's or deleted-attachment link, and stored content that is missing or fails authentication, all answer 404 `attachment.not-found`; `link` missing or over 64 characters is 400 `request.invalid` with `errors.link` |

Every module route group is gated by its module flag: when the flag is disabled the API answers `404 application/problem+json` with `code: feature.disabled` and `instance` set to the request path, the web shell hides the module's navigation entry, and the module's web segment renders the not-found page inside the shell with status 404.
