# Routing register

Every API route group and web route in the system. API routes follow `/api/<domain>/<module>/<resource>`; web routes mirror them without the `/api` prefix. Exempt prefixes: `/api/auth/*`, `/api/platform/*`, `/healthz/*`.

Every API route requires a signed-in person unless this register marks it anonymous ([ADR-0031](adr/0031-sign-in-through-entra-in-the-api.md)): without a session a request answers 401 `request.unauthenticated` without a `Location` header, and so does an anonymous request to a path no route matches (a signed-in one answers 404 `resource.not-found`); a signed-in request a policy refuses answers 403 `request.forbidden`. The anonymous routes are the permanent ones (`/healthz/live`, `/healthz/ready`, `GET /api/auth/login`, and in Development `/openapi/erp.json` and `/scalar`) and the transitional platform routes marked "anonymous until `authentication-web-login-page-and-session-integration`"; `ModuleCatalogTests` fails on any other.

Every API response carries `X-Correlation-ID`, and every non-2xx body is `application/problem+json` with `type` (`/problems/<code>`), `code`, `status`, `title`, `instance` and `traceId` (the correlation id); validation problems add `errors`, keyed by camelCase member paths (`orderItems[0].description`; `""` for a result that names no member, except a class-level attribute result on a nested object, keyed by that object's path such as `customer`; the exact table is in HTTP conventions). Every module route also documents 400 (validation), 404 (unknown resource or disabled module), 429 (rate limit), 500 and 504 (timeout). Any route except `/healthz/*` may answer 429 `rate-limit.exceeded` with `Retry-After` (anonymous callers are counted per client address, signed-in callers per actor; `Erp:Platform:RateLimiting`; the attachments upload also answers it when `Erp:Platform:Attachments:MaxConcurrentUploads` uploads are already in flight). Any route may also answer 400 `request.host-not-allowed` (a `Host` outside `Erp:Platform:Host:AllowedHosts`), 413 `request.too-large` (a body over `Erp:Platform:Host:MaxRequestBodyBytes`, or for the attachments upload over `Erp:Platform:Attachments:MaxSizeBytes` plus 64 KiB) and 504 `request.timeout` (a request running past `Erp:Platform:Host:RequestTimeout`); see [request pipeline](architecture/request-pipeline.md). The committed contract of these routes is [`docs/openapi/erp.json`](openapi/erp.json); the rules are in [HTTP conventions](architecture/http-conventions.md).

## Host endpoints

| Route | Auth | Purpose |
|---|---|---|
| `GET /healthz/live` | anonymous | process liveness (container health check); runs no check; never rate limited and left out of request metrics |
| `GET /healthz/ready` | anonymous | readiness including dependencies (`self`, `database:<schema>` per catalogue context, `storage:attachments`, which only degrades, and `app-configuration` with the App Configuration source, which only degrades), each check limited to 2 seconds: `200 text/plain` `Healthy` or `Degraded`, or `503 application/problem+json` `service.unavailable` naming no check; never rate limited and left out of request metrics |
| `GET /openapi/erp.json` | anonymous, Development only | OpenAPI 3.1 document, identical to the committed [`docs/openapi/erp.json`](openapi/erp.json) apart from formatting |
| `GET /scalar` | anonymous, Development only | API reference UI |
| `GET /api/platform/features` | anonymous until `authentication-web-login-page-and-session-integration` | every feature flag of the catalog with its evaluated state (`{ features: [{ name, enabled }] }`), read by the web shell to hide disabled modules |

Two conventions apply to the routes this register lists, from the module that first uses them: a route that creates something carries `.RequireIdempotencyKey()`, so the caller sends an `Idempotency-Key` header with a UUID, a repeat of the same request replays the first response with `Idempotency-Replayed: true`, and the same key with a different body answers 422; a route that lists something accepts `?page=&pageSize=&sort=&filter=` with per-route field allow-lists. Both grammars are in `docs/architecture/application-pipeline.md`. `system-info/startups` predates the paging convention and takes `?take=` instead; `GET /api/platform/attachments` is the first paged route. The two attachment routes that create something, the upload and `download-links`, deliberately carry no idempotency key (ADR-0022): the middleware would buffer a whole upload before the endpoint runs, and would store a download link's token in plain text, while repeating either request is harmless.

## Sign-in endpoints

The API signs people in with Microsoft Entra ID and keeps the session in the cookie `__Host-erp-session` ([HTTP conventions](architecture/http-conventions.md), section "Sign-in and the session"; [ADR-0031](adr/0031-sign-in-through-entra-in-the-api.md)). The group `/api/auth` (tag `Auth`, no feature flag) documents 429, 500 and 504. The three handler paths are answered by the authentication middleware before the rate limiter, so no limit applies to them, and they are not in the OpenAPI document.

| Route | Name | Auth | Answers |
|---|---|---|---|
| `GET /api/auth/login?returnUrl=` | `Auth.Login` | anonymous | request record `LoginRequest`; `returnUrl` a local path of at most 2048 visible ASCII characters starting with `/`, `/` when absent; `302` to the tenant's Entra authorize endpoint (`response_type=code`, `response_mode=form_post`, an S256 PKCE challenge, scopes `openid profile offline_access`, `redirect_uri` `Erp:Platform:Identity:WebOrigin` + `/api/auth/signin-oidc`), or for a signed-in caller `302` straight to `returnUrl`; any other `returnUrl` is 400 `request.invalid` with `errors.returnUrl` and sets no cookie |
| `POST /api/auth/logout` | `Auth.Logout` | signed in | clears the session cookie and answers `302` to Entra's end-session endpoint with `post_logout_redirect_uri` `WebOrigin` + `/api/auth/signout-callback-oidc`; without a session 401 `request.unauthenticated` |
| `POST /api/auth/signin-oidc` | — (handler path) | anonymous | the callback Entra posts the code to (registered redirect URI); issues the session cookie and answers `302` to the return address; a declined, forged or otherwise failed callback answers `302` to `/login?error=sign-in-failed` and sets no session |
| `GET /api/auth/signout-callback-oidc` | — (handler path) | anonymous | where Entra returns after sign-out (registered redirect URI); `302` to `/login` |
| `/api/auth/signout-oidc` | — (handler path) | anonymous | the handler's front-channel sign-out path; not registered with Entra (no registration sets a front-channel logout URL), so Entra never calls it |

Routes and route names (table below); the flows are in [attachments](architecture/attachments.md). The web page lists attachments through the list kit: 20 rows a page by default (`?size=` 10, 20, 50 or 100), newest first, sortable by name, type, size and upload time and filtered by name, type and upload date; `?page=` must be an ASCII whole number from 1 to the last page the API's `PageRequest` accepts for the chosen size (`lastRequestablePage` in `frontend/apps/web/src/shared/api/paging.ts`), and a malformed address or a page past the last redirects to the canonical address of the view it can show, keeping the other parameters ([list addresses](#list-addresses)). The upload policy and the list load independently, so each card shows its own failure. The page uploads through the shared drop zone with progress (refusing a file over the policy's size or of another type before sending it, and showing the API's reason for a refusal), downloads through a fresh link opened by a temporary same-origin `<a download>`, so the page stays put and a link that cannot be created shows in the row, and deletes after a confirmation dialog, moving focus to the "Stored files" heading, taking the row off the list and the count down at once and confirming in a toast (a file another tab already deleted counts as deleted, with the note "It had already been deleted.", and a refusal stays in an error toast until closed) |

Platform / Attachments routes (every attachment is `{ id, fileName, contentType, sizeBytes, sha256, scanStatus ("notScanned" or "clean"), createdAt, createdBy }`):

| Route | Name | Answers |
|---|---|---|
| `GET /api/platform/attachments` | `Platform.Attachments.List` | `200` `{ items, page, pageSize, totalCount, totalPages }`, newest first unless sorted; `page`, `pageSize` (1 to 200, default 50), `sort` over `fileName`, `contentType`, `sizeBytes`, `createdAt`, `filter` over `fileName`, `contentType`, `createdAt`; 400 `query.*` |
| `GET /api/platform/attachments/policy` | `Platform.Attachments.GetUploadPolicy` | `200` `{ maxSizeBytes, allowedContentTypes }` (types sorted) |
| `POST /api/platform/attachments` | `Platform.Attachments.Upload` | `multipart/form-data`, the first part with a file name is the file, and that name must end in an extension of the declared type; body limit `MaxSizeBytes` + 64 KiB, timeout policy `platform.attachments.transfer` and rate-limiter policy `platform.attachments.uploads` (at most `MaxConcurrentUploads` uploads in flight per API process); no `Idempotency-Key`. `201` with `Location: /api/platform/attachments/{id}` and the attachment; 400 `attachment.file-missing`, `attachment.file-name-invalid`, `attachment.empty`, `attachment.incomplete`; 413 `attachment.too-large` or `request.too-large`; 415 `attachment.multipart-required`, `attachment.unsupported-type`, `attachment.extension-mismatch`, `attachment.content-mismatch` (leading bytes, or text that is not UTF-8 without NUL anywhere in the file); 422 `attachment.infected`; 429 `rate-limit.exceeded` with `Retry-After` when the concurrency cap is reached |

| `DELETE /api/platform/attachments/{id}` | `Platform.Attachments.Delete` | `204`; the attachment is soft-deleted and its links stop working; 404 `attachment.not-found` |

| `GET /api/platform/attachments/{id}/content?link=` | `Platform.Attachments.Download` | request record `RedeemDownloadLinkRequest`, command `RedeemDownloadLinkCommand`; `200` with the original bytes, `Content-Type` the stored content type (the document declares `application/octet-stream`), `Content-Disposition: attachment` with the stored file name and `Content-Length`; timeout policy `platform.attachments.transfer`; each download recorded; a wrong, expired, other person's or deleted-attachment link, and stored content that is missing or fails authentication, all answer 404 `attachment.not-found`; `link` missing or over 64 characters is 400 `request.invalid` with `errors.link` |

Every module route group is gated by its module flag: when the flag is disabled the API answers `404 application/problem+json` with `code: feature.disabled` and `instance` set to the request path, the web shell hides the module's navigation entry, and the module's web segment renders the not-found page inside the shell with status 404.

## List addresses

A list page keeps its view in its address ([ADR-0026](adr/0026-server-driven-lists-and-the-data-table.md), `apps/web/src/shared/lists`): each filter of its definition (`<param>=<text>`, `<param>=<value>` repeated for a choice, `<param>From` and `<param>To` as `yyyy-MM-dd` for a date range), then `sort=<field>:<asc|desc>`, `size=<page size>`, `page=<n>` and `hide=<column>,<column>`. A value equal to its default is left out, so the first page in the default order is the bare path; an address with an unknown parameter, a malformed value, a page size the list does not offer, a page past the last or a reversed date range redirects to the address of the view it can show. A list's API call always sends `sort` explicitly and turns a date range on a timestamp into India Standard Time days (`gte` the first day's midnight, `lt` the midnight after the last day).
