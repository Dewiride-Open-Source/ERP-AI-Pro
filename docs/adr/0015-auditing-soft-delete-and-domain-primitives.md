# ADR-0015: Auditing, soft delete, row versions, the actor model and the domain primitives

Status: accepted
Date: 2026-09-22

## Context

ADR-0008 fixes one database with one schema per module and ADR-0013 fixes how a module context is wired and how strongly-typed ids, `decimal`, `DateTimeOffset` and value objects are mapped. Both leave open how audit columns, soft delete, optimistic concurrency and the domain value types (money, currency, percentages, Indian financial years) are applied uniformly across hundreds of modules without per-entity configuration, and who the acting user is when a row is written by a hosted service, the test database host or the migrator, where no HTTP request exists.

The owner's rules (root `CLAUDE.md` §5 Data) constrain the design: ids are `Guid.CreateVersion7()` wrapped in strongly-typed structs; money is `decimal(19,4)` with a currency code; timestamps are `DateTimeOffset` in UTC; calendar dates are `DateOnly`; concurrency goes through a `RowVersion`; audit columns are written by an interceptor, never by domain code; soft delete exists only for master data, because financial documents are immutable after issue and are corrected by further documents; every statutory rate, threshold and rounding rule is an effective-dated parameter record with its government source, never a literal in code or tests. India observes no daylight-saving time, so Indian Standard Time is a fixed offset. Sign-in is Entra ID only (ADR-0004), so every authenticated principal carries an object identifier claim.

## Decision

- Opt-in interfaces in `Dewiride.Erp.BuildingBlocks.Kernel.Domain`, all getter-only: `IAuditable` (`DateTimeOffset CreatedAt`, `Guid CreatedBy`, `DateTimeOffset? ModifiedAt`, `Guid? ModifiedBy`), `ISoftDeletable` (`bool IsDeleted`, `DateTimeOffset? DeletedAt`, `Guid? DeletedBy`) and `IVersioned` (`byte[] RowVersion`). Implementers declare the properties with `private set`; the interceptor writes them through the change tracker (`EntityEntry.Property(name).CurrentValue`), so no domain method assigns an audit field and no domain type references the actor or the clock.
- `AuditingSaveChangesInterceptor(IActorContext actor, TimeProvider timeProvider)` in `Dewiride.Erp.BuildingBlocks.Persistence.Auditing` is a scoped `SaveChangesInterceptor`. Its synchronous `SavingChanges` throws `NotSupportedException`: every database write is `SaveChangesAsync`. `SavingChangesAsync` calls the static `Stamp(ChangeTracker, DateTimeOffset now, Guid actorId)` with `timeProvider.GetUtcNow()` and `actor.ActorId`, which walks every tracked entry and owns every audit and deletion column. `Added`: `IAuditable` gets `CreatedAt`/`CreatedBy` = now/actor and `ModifiedAt`/`ModifiedBy` = `null`; `ISoftDeletable` gets `IsDeleted` = `false` and `DeletedAt`/`DeletedBy` = `null`. `Modified`: `IAuditable` gets `ModifiedAt`/`ModifiedBy` = now/actor with `CreatedAt`/`CreatedBy` marked unmodified so the original values stay in the row; `ISoftDeletable` is stamped by the `IsDeleted` transition — `false` → `true` (a domain method flagging the row) sets `DeletedAt`/`DeletedBy` = now/actor, `true` → `false` (a domain restore) clears them, and no transition marks `IsDeleted`, `DeletedAt` and `DeletedBy` unmodified, so neither a tampered value nor `Update(detached)` can resurrect a deleted row or rewrite who deleted it. `Deleted` + `ISoftDeletable`: a row whose original `IsDeleted` is already `true` goes back to `Unchanged` (a second delete keeps the first deletion's stamps); otherwise the state becomes `Modified`, `IsDeleted` = `true`, `DeletedAt`/`DeletedBy` = now/actor, plus the `Modified` stamps when the entity is also `IAuditable`. A `Deleted` entity that is not `ISoftDeletable` is deleted for real. `ModuleDbContext` sets `ChangeTracker.CascadeDeleteTiming` to `OnSaveChanges`, so `Remove(root)` on a soft-deletable aggregate does not cascade into its loaded child entities or owned types: EF cascades only entries that are still `Deleted` after the interceptor ran, the root is `Modified` by then, and the child rows stay (reachable through the root, which is hidden); a hard-deleted root still cascades at save time as EF always did. `BulkWriteGuardInterceptor` (`IQueryExpressionInterceptor`, singleton, attached to every module context) throws `InvalidOperationException` for `ExecuteDelete`/`ExecuteDeleteAsync` on an `ISoftDeletable` type and for `ExecuteUpdate`/`ExecuteUpdateAsync` on an `IAuditable` or `ISoftDeletable` type, because both run without the change tracker and would skip the stamps; bulk operations stay available for every other entity type.
- `ModuleDbContext.OnModelCreating` calls `ModelRules.ApplySoftDelete().ApplyRowVersion()` after `ApplyConfigurationsFromAssembly`. `ApplySoftDelete` adds the named query filter `SoftDeleteFilter.Name` (`"SoftDelete"`, expression `entity => !entity.IsDeleted`) to every entity type that introduces `ISoftDeletable` into its hierarchy; EF Core allows a filter only on the root of a hierarchy, so a derived type that implements it while its root does not, and an owned type that implements it, fail model building with an `InvalidOperationException` naming the type (derived types of a soft-deletable root inherit the filter). `ApplyRowVersion` maps `IVersioned.RowVersion` with `IsRowVersion()` on the type that introduces the interface (SQL Server `rowversion`, concurrency token, generated on add and update), so a stale update surfaces as `DbUpdateConcurrencyException` from `SaveChangesAsync`. Administrative reads that need deleted rows call `SoftDeleteFilter.IncludeDeleted<TEntity>()`, which is `IgnoreQueryFilters([SoftDeleteFilter.Name])` and leaves every other named filter in force.
- Actor model. `IActorContext` (`Guid ActorId`, `bool IsAuthenticated`) lives in `Dewiride.Erp.BuildingBlocks.Application.Actors` with `ActorIds.System` (`00000000-0000-0000-0000-000000000001`) and `ActorIds.Anonymous` (`00000000-0000-0000-0000-000000000002`). `SystemActorContext` returns `(ActorIds.System, false)` and serves hosts without HTTP. `HttpActorContext` (`internal`, `Dewiride.Erp.BuildingBlocks.Endpoints.Actors`) reads `IHttpContextAccessor` once, lazily, per scope: no `HttpContext` → `(ActorIds.System, false)`; a principal that is not authenticated → `(ActorIds.Anonymous, false)`; an authenticated principal → the `http://schemas.microsoft.com/identity/claims/objectidentifier` claim, else the short `oid` claim, parsed as a `Guid` → `(objectId, true)`; an authenticated principal without a parseable object identifier → `InvalidOperationException`, because every ERP sign-in is an Entra identity. Registration precedence: `AddErpPersistenceCore` registers `TryAddSingleton(TimeProvider.System)`, `TryAddScoped<IActorContext, SystemActorContext>()` and `TryAddScoped<AuditingSaveChangesInterceptor>()`; `AddErpEndpoints` calls `AddHttpContextAccessor()` and `services.Replace(ServiceDescriptor.Scoped<IActorContext, HttpActorContext>())`, which wins whichever of the two runs first (`Replace` removes an existing registration; a later `TryAdd` is a no-op). `AddModuleDbContext<TContext>` resolves the interceptor from the scoped provider and adds it to every module context with `AddInterceptors`.
- Money primitives in `Dewiride.Erp.BuildingBlocks.Kernel.Monetary`, BCL-only. `Currency` is a `readonly record struct` over a fixed ISO 4217 table (`Inr`, `Usd`, `Eur`, `Gbp`, `Aed`, `Sgd`, `Aud`, `Cad` with 2 minor units, `Jpy` with 0) exposing `Code`, `MinorUnits`, `All`, `FromCode` (`ArgumentException` for an unknown code), `TryFromCode` and `IsDefined` (`false` for `default(Currency)`); a currency outside the table is added by a code change reviewed in a pull request, never by configuration or data. `Money` is a `readonly record struct` `(decimal Amount, Currency Currency)` whose constructor rejects an undefined currency; `+`, `-`, the comparison operators and `CompareTo` refuse mixed currencies with `InvalidOperationException`, and unary `-`, `*` and `/` by `decimal` keep the currency; `RoundToMinorUnits()` rounds `AwayFromZero` at the currency's minor units and `RoundToWholeUnits()` rounds `AwayFromZero` to whole units, the rounding of CGST Act 2017 s.170 that tax code applies to amounts payable; `Allocate(params int[] ratios)` and `Allocate(int parts)` split the value in minor units by largest remainder so the parts always sum exactly to the rounded total, ties go to the earlier index, empty, negative or all-zero ratios throw `ArgumentException` and a non-positive part count throws `ArgumentOutOfRangeException`; `ToString`/`ISpanFormattable` give `1234.50 INR` (`F<minor units>`; invariant culture unless a format provider is passed) and `IParsable` reads `<amount> <code>` under the same rule. `Percentage` is a `readonly record struct` `(decimal Value)` in percent units with `Zero`, `Hundred`, `AsFraction`, `FromFraction`, `Of(Money)`, `+`, `-`, comparisons and `ToString` of `18%` / `12.5%`.
- Persistence of `Money` by convention: `ModuleDbContext.ConfigureConventions` declares `Properties<Currency>().HaveConversion<CurrencyConverter>().HaveMaxLength(3).AreUnicode(false).AreFixedLength()` and `ComplexProperties<Money>()`, so every `Money` property of every entity maps as a complex type to `<Property>_Amount decimal(19,4)` and `<Property>_Currency char(3)` with no per-entity configuration.
- Time primitives in `Dewiride.Erp.BuildingBlocks.Kernel.Time`. `IndianStandardTime` is the fixed offset `+05:30` (`Offset`, `ToIst`, `IstDate`, `StartOfIstDay(DateOnly)`, `Today(TimeProvider)`) with no time-zone database dependency. `FinancialYear` is a `readonly record struct` over `int StartYear` (1 to 9998, `ArgumentOutOfRangeException` otherwise): `Start` 1 April, `End` 31 March of the next calendar year, `Label` `2026-27`, `AssessmentYearLabel` `2027-28`, `Next`, `Previous`, four `Quarters`, `FromDate(DateOnly)` (April onwards → that year, January to March → the previous year), `Current(TimeProvider)` from the IST date, `Contains`, `QuarterOf` (`ArgumentOutOfRangeException` outside the year), comparisons, and `Parse`/`TryParse` of the label, which rejects a label whose end suffix does not follow the start year (`2026-28`). `FinancialQuarter` is `(FinancialYear Year, int Number)` with `Number` 1 to 4: Q1 April–June, Q2 July–September, Q3 October–December, Q4 January–March of the next calendar year; `Start`, `End`, `Label` `Q1 2026-27`, `Contains`.
- JSON: each primitive carries a `[JsonConverter]` attribute, so System.Text.Json applies the shape everywhere — minimal API binding, responses, OpenAPI and tests — without registration. `MoneyJsonConverter` writes `{"amount": 1234.5, "currency": "INR"}` and reads it with case-insensitive property names, skipping unknown properties and throwing `JsonException` when `amount` or `currency` is missing, of the wrong token type or an unknown code; `CurrencyJsonConverter` writes and reads the code string; `PercentageJsonConverter` writes and reads a plain number of percent; `FinancialYearJsonConverter` writes and reads the label string. Every converter answers a wrong token type with `JsonException`, which minimal APIs turn into a 400.

## Consequences

- An entity opts in by implementing an interface or declaring a `Money` property; there is no entity configuration for audit columns, the soft-delete filter, the row version or the money columns, and the BuildingBlocks integration tests prove the conventions against SQL Server on `SampleAggregate`.
- Every context write is `SaveChangesAsync`; a synchronous `SaveChanges` fails at the first write with `NotSupportedException`, so a test catches it before production does. `ExecuteDeleteAsync` on a soft-deletable type and `ExecuteUpdateAsync` on an auditable or soft-deletable type fail at query compilation with `InvalidOperationException`; on every other type they remain available, and the `SoftDelete` filter still applies to their source query.
- Deleting an `ISoftDeletable` entity through the context never removes the row or its child rows: `IsDeleted` rows stay in the table and every query hides them unless it calls `IncludeDeleted()`. No path through a module context hard-deletes master data.
- A stale `IVersioned` update surfaces as `DbUpdateConcurrencyException` from `SaveChangesAsync`; translating it into an `ErrorKind.Conflict` result is the application pipeline's job, not the interceptor's, so the persistence layer never swallows a lost update.
- Rows written outside a request — by a hosted service, the test database host or the migrator — carry `ActorIds.System`; rows written by an unauthenticated request carry `ActorIds.Anonymous`; both are distinguishable from any Entra object id.
- A currency outside the fixed table is a code change, so a new trading currency is reviewed like any other rule.
- The primitives carry no rates, slabs or thresholds; statutory tests draw their amounts from parameter records, and only the s.170 rounding method lives in code because it is a method, not a rate.
- `Percentage.Of(Money)` returns an unrounded `Money`; the caller rounds with `RoundToMinorUnits()` or `RoundToWholeUnits()` at the point the statute defines.
