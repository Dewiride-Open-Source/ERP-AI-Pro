# ADR-0023: Design tokens, the shared theme stylesheet and generated primitives

Status: accepted
Date: 2026-09-26

## Context

The `web-foundation-design-tokens-and-theme-package` sub-phase turns `@dewiride/erp-ui` into the design system every page builds on: tokens for colour, typography, spacing, radius and motion, a theme stylesheet the whole workspace can import, the shadcn primitives, and a `/design/kitchen-sink` page that Playwright screenshots in both themes. Facts that shape the decision:

- **Radix, not Base UI.** The sub-phase scope says "shadcn init (Base UI primitives …)". shadcn made Base UI the default of `init` and `create` on 2026-07-02 (changelog `2026-07-base-ui-default`) while stating that Radix is not deprecated and every component keeps shipping for both. ADR-0007 and ADR-0009 chose shadcn/ui on Radix (`radix-ui`), and `packages/ui/components.json` was already initialised with the `radix-nova` style, which `components.json` does not allow to change after initialisation. Within `radix-nova`, `combobox` imports `@base-ui/react`, and the new `toast` exists only for Base UI.
- **One mixed stylesheet.** `packages/ui/src/styles/globals.css` held the Tailwind import, every token and the base layer, and was the only CSS export. Tailwind documents sharing a theme through a file that never imports `tailwindcss` and is imported after it; a compile with the repository's `tailwindcss@4.3.3` showed that importing `tailwindcss` twice emits preflight twice. There were no typography, spacing, elevation, layer or duration tokens: `fade-up` ran 500 ms against the 150–300 ms rule of `frontend/CLAUDE.md`, durations were literals (`duration-200`, `duration-100`), and the shell used literal `z-40`, `h-14` and `max-w-6xl px-4 sm:px-6`.
- **Contrast.** Computed from the OKLCH values of the `globals.css` this sub-phase started from (WCAG 2.2 ratios, over `background` unless another surface is named), these pairs were under 4.5:1 for text. In light, `success` as text was 3.18:1 and `warning` 1.96:1, on `card` 3.32:1 and 2.05:1, and on their own 10 % tints 2.84:1 and 1.83:1; `destructive` on its own 10 % tint (the destructive button and badge) was 3.92:1 and `success-foreground` on `success` 3.23:1; the default button's hover (`primary-foreground` on `hover:bg-primary/80`) was 4.21:1, 4.16:1 on `card`, and the destructive button's hover (`hover:bg-destructive/20`) 3.34:1. In dark, the destructive button was 4.26:1 when hovered (`dark:hover:bg-destructive/30`), 3.91:1 on `card`, and 4.36:1 at rest (`dark:bg-destructive/20`) inside the `bg-muted/50` footer of a card or dialog. The `success`, `warning` and `destructive` tints were each lower still inside such a footer. `input`, the border that identifies a text field, checkbox or radio, was 1.25:1 against `background` and 1.31:1 against `card` in light, and 1.45:1 and 1.51:1 in dark, against the 3:1 of SC 1.4.11. Every other pair passed in both themes. The light `chart-2` (2.27:1) and `chart-3` (1.96:1) are under 3:1 as graphical objects but decorate nothing that carries meaning yet.
- **Class merging.** `packages/ui/src/lib/utils.ts` re-exported the `cn` package's `cn` (ADR-0014), whose merge tables know only Tailwind's own scales. With the new tokens they would read a type role such as `text-title` as a colour, so `cn("text-base", "text-title")` would keep both sizes, and they would keep a named class such as `px-gutter`, `gap-section` or `ease-standard` beside the numeric or keyword utility a caller passes to replace it, where the named utility, emitted later in the stylesheet, wins. `badge`, `button` and `card` imported that `cn` from `@dewiride/erp-ui/lib/utils`; every other generated primitive imported the package's `cn` directly, as the registry emits it.
- **Accessibility gaps in generated primitives.** The registry's `MenubarTrigger` carries `outline-hidden` and no focus or highlighted style; `TabsContent` is a Tab stop (Radix gives it `tabIndex={0}`) with `outline-none`; Radix's `Accordion.Header` always renders an `h3`, whatever heading it sits under.
- **`exactOptionalPropertyTypes` and the generated primitives.** `packages/config/tsconfig/base.json` sets `exactOptionalPropertyTypes: true`. The registry versions of `context-menu`, `dropdown-menu` and `menubar` (each `*CheckboxItem` passes a destructured `checked` explicitly), `slider` (`defaultValue={defaultValue} value={value}`) and `sonner` (`theme as ToasterProps["theme"]`, which includes `undefined`) fail with TS2375. `@dewiride/erp-ui` is consumed as source through its package exports and `skipLibCheck` only skips `.d.ts` files, so the web app's `tsc` and `next build` typecheck these files as their own; relaxing the flag in `packages/ui/tsconfig.json` alone changes nothing. Compiling the primitives to `dist` with the flag off, as `@dewiride/erp-api-client` does, would add a second build, split the exports between `src` and `dist` and force a rebuild before `dev`, `lint` and `typecheck`. `progress.tsx` already carried an unrecorded edit (it passes `value` to the Radix root, which gives the bar its `aria-valuenow`, asserted by `e2e/tests/platform/attachments/files.spec.ts`), although ADR-0014 recorded that "`shadcn add` and `shadcn diff` produce compilable files without manual edits" and `frontend/CLAUDE.md` said primitives "change only through `shadcn add`/`shadcn diff`". In CLI 4.21.0 `shadcn diff` is deprecated in favour of `shadcn add <item> --diff` and reports "No updates found" even for a file that differs from the registry.
- **The sidebar.** `sidebar` requires the generated `use-mobile` hook, which sets state inside an effect and fails the `react-hooks/set-state-in-effect` rule of the shared ESLint preset; nothing needs a sidebar before the authenticated shell.
- **Providers.** The `radix-nova` `Tooltip` does not wrap a `TooltipProvider`, and `sonner` renders nothing without a mounted `Toaster`.

## Decision

- **Radix stays.** `packages/ui` keeps the `radix-nova` style. `shadcn init`, `apply`, `migrate base-color` and `add font-*` are never run there, and no `@base-ui/*` package enters the lockfile. `combobox` and `toast` are not installed (sonner is the toast). This supersedes the "Base UI primitives" wording of the sub-phase scope, as its roadmap note records.
- **Two stylesheets, one entry.** `globals.css` is the only file that imports `tailwindcss`: `@import "tailwindcss"; @import "./theme.css"; @source "../**/*.{ts,tsx}";`. `theme.css` holds the font families, the colour values on `:root`/`.dark`, their `@theme inline` mapping and the radius scale, imports `tw-animate-css`, `shadcn/tailwind.css`, `tokens/{typography,layout,elevation,focus,motion}.css` and `base.css`, and never imports Tailwind. `@dewiride/erp-ui` exports both (`./globals.css`, `./theme.css`); `components.json` names `theme.css` in `tailwind.css`. The font families stay in `theme.css` because shadcn CLI 4.21.0 keeps the registry's `font-heading` class in a generated primitive only when that one file contains `--font-heading:`, without following its `@import`s; a token a generated primitive depends on is always declared there. An app loads `globals.css` or writes `@import "tailwindcss"; @import "@dewiride/erp-ui/theme.css";` plus an `@source` for the ui sources; a package or CSS Module uses `@reference "@dewiride/erp-ui/globals.css"`.
- **Token placement.** A value that changes under `.dark` or a media query is a plain custom property mapped in `@theme inline`; a literal scale lives in `@theme`; a value that must not produce a utility stays a plain property used as `utility-(--name)`; no `--tw-*` names; a type role never reuses a colour name. The tokens are: 38 colours (`info` and `info-foreground` added, completing the four states sonner uses); the type roles `text-title`, `text-heading`, `text-body`, `text-caption` and `text-eyebrow` with `"cv11", "ss01", "tnum"` on `font-sans`; `px-gutter` (1rem, 1.5rem from `sm`), `gap-section`, `h-header`, `max-w-page`; the unchanged shadcn radius scale; Tailwind's shadow geometry tinted by `--elevation-color-*`; the layers `--layer-sticky` (40) and `--layer-overlay` (50, the literal `z-50` of the generated portals); the `focus-ring` utility (a 2px outline in `ring`, offset 2px, on `:focus-visible`); and the motion tokens `--motion-duration-fast|normal|slow|ambient` (150ms, 200ms, 300ms, 6s) and `--motion-ease-standard|enter`, which drive the default transition, `ease-standard`, `ease-enter`, `animate-fade-up` (now 300 ms) and `animate-glow`.
- **Class merging and the type-role lint rule.** `utils.ts`, the `cn` of application code and composites and the `aliases.utils` entry of `components.json`, builds `cn` with `createCn` from `cn/config`: the `font-size` class group gains the five type roles (`typeRoles`, exported from the same file), and the theme scales gain the named tokens (`spacing` `gutter`, `section`, `header`; `container` `page`; `ease` `standard`, `enter`), so a role replaces a size and a caller's `px-4` or `ease-in-out` replaces `px-gutter` or `ease-standard`. Every generated primitive that merges classes, `badge`, `button` and `card` included, imports the package's default `cn`, as the registry emits it; because those tables read a role as a colour, a role passed in a primitive's `className` would sit beside the primitive's own size and could drop its text colour, so roles go on plain elements only. `@dewiride/erp-config/eslint/type-roles` (`type-roles.mjs`, typed by `type-roles.d.mts`) exports `typeRoles` and the `no-restricted-syntax` selectors that both the `next` and the `react-library` ESLint presets apply: a role class anywhere in the `className` of a capitalised or member-expression JSX element fails lint, inside `cn(...)` and template literals too. `src/lib/utils.test.ts` fails when `tokens/typography.css`, `typeRoles` in `utils.ts` and `typeRoles` in the lint module name different roles, or when a spacing or container name declared in `tokens/layout.css` or an easing name declared in `tokens/motion.css` does not merge with Tailwind's scale.
- **Contrast gates.** In light, `primary` becomes `oklch(0.47 0.22 275)`, with `ring`, `chart-1`, `sidebar-primary` and `sidebar-ring`, which carry the same value; `destructive` becomes `oklch(0.48 0.19 27)`, `success` `oklch(0.5 0.12 155)` and `warning` `oklch(0.52 0.12 60)` with a light `warning-foreground`. In dark, `destructive` becomes `oklch(0.84 0.12 22)`. So each status colour reads as text on `background`, on `card` and on its own tint over every surface a control sits on, and both buttons keep 4.5:1 when hovered. `input` becomes `oklch(0.64 0.015 265)` in light and `oklch(1 0 0 / 35%)` in dark. A unit test in `packages/ui` (`src/styles/contrast.test.ts` over `src/lib/oklch.ts`) fails when, in either theme, an `X-foreground` on `X`, `foreground` or `muted-foreground` on `background`, `card` or `muted`, or `primary` or a status colour as text on `background` or `card` falls under 4.5:1; when `primary` or a status colour on its own tint (10 % light, 20 % dark), `destructive` on its hover tint (20 % light, 30 % dark) or `primary-foreground` on `primary` at 80 % falls under 4.5:1 over any of `background`, `card`, `popover` and the `bg-muted/50` footers of cards and dialogs; or when `input` against `background` and `card`, or `ring` against `background`, falls under 3:1. The chart palette is validated by `reporting-web-dashboards-and-reports`, which brings the first chart.
- **Reduced motion in one place.** `tokens/motion.css` collapses the three interface durations to 0.01ms inside one `prefers-reduced-motion: reduce` block and keeps one global safety net in `@layer base` (`animation-duration` and `transition-duration` 0.01ms, one iteration, `scroll-behavior: auto`, all `!important`), which also covers the literal durations inside generated primitives. The value is 0.01ms rather than 0 because, per MDN, a transition whose duration and delay are both 0s fires no transition events. Components add no `motion-reduce:` variants of their own.
- **Theme wiring and providers.** `next-themes` keeps the class strategy with `defaultTheme="system"`, `enableSystem`, `disableTransitionOnChange` and the CSP nonce; the root layout declares `viewport.colorScheme` `"light dark"` and mounts `TooltipProvider` around the page and one `Toaster` inside `ThemeProvider`. `ThemeToggle` is a Radix `RadioGroup`, one tab stop in which all four arrow keys move and select (it sets no `orientation`, because a horizontal one makes Radix ignore Up and Down), and its checked item carries `forced-colors:data-[state=checked]:outline-2`, a solid 2 px outline that forced-colours mode keeps where it replaces the item's background fill and removes its shadow.
- **Base rules.** `base.css` sets `scroll-padding-top: calc(var(--spacing-header) + var(--spacing) * 2)` on `html`, so focus the keyboard moves and in-page anchor targets stop 0.5rem below the sticky header, clear of the focus indicator drawn outside the control (WCAG 2.2 SC 2.4.11), and no element carries a scroll margin of its own. Sonner appends a `<style>` whose unlayered `[data-sonner-toaster]` rule sets a system font stack; an unlayered rule beats any rule inside a cascade layer, so `base.css` ends with the unlayered `html [data-sonner-toaster] { font-family: var(--font-sans); }`, whose higher specificity wins wherever sonner's `<style>` lands, and the generated `sonner.tsx` stays untouched.
- **Generated primitives change through the CLI plus registered patches.** Primitives are added with `shadcn add` (a `--dry-run` first, never `--overwrite` except to refresh a primitive to the registry version) and reviewed with `shadcn add <item> --dry-run --diff`. A generated file may carry a local patch only when it is the smallest change that makes the registry file compile or behave correctly, and only when it is recorded in the register of `docs/architecture/design-system.md` in the same change, with its reason and the check that fails if it is lost; the file itself carries no comment. The register holds `progress` (`value` passed to the Radix root), the `CheckboxItem` of `context-menu`, `dropdown-menu` and `menubar` (`checked` through props), `slider` (`value` and `defaultValue` through props), `sonner` (`theme` narrowed with `NonNullable`), the `MenubarTrigger` and `TabsContent` focus indicator (`focus-ring`, the full-strength outline, because on these borderless elements the half-strength ring the other generated controls pair with `border-ring` would be the whole indicator, below 3:1 and gone in forced colours) and the `AccordionTrigger` `headingLevel` prop (2 to 6, default 3, rendered through `AccordionPrimitive.Header asChild`). A refresh with `--overwrite` re-applies every register entry of that file.
- **Deferred.** `sidebar` moves to `authentication-authenticated-application-shell`, which must settle the `use-mobile` hook before installing it; the `./hooks/*` export arrives with it. The styling of `app/global-error.tsx`, which does not receive the global styles, moves to `web-foundation-feedback-motion-and-accessibility-baseline`, as does the choice of the approved `motion` package.
- **The kitchen sink.** `/design/kitchen-sink` (`features/platform/design`, no `nav.ts`) renders every token group, every colour token as a swatch, every installed primitive in its states, the composites and the excluded registry items with their reasons. It is available in every environment, because Playwright screenshots the production build, the page holds no data and it inherits `robots: noindex`; it appears in no navigation, and inside the `(app)` shell it requires a signed-in user from the authentication phase on.
- **Earlier decisions this changes.** ADR-0014: this decision amends its `utils.ts` decision. `packages/ui/src/lib/utils.ts` no longer re-exports `cn` from the package; it is hand-written and builds a configured `cn` with `createCn` (see "Class merging and the type-role lint rule"), while the generated primitives keep importing the package's `cn` directly, so the two import shapes now merge classes differently by design. Its consequence that `shadcn add` and `shadcn diff` produce compilable files without manual edits no longer holds for the five files patched to compile (`context-menu`, `dropdown-menu`, `menubar`, `slider`, `sonner`), and the rule "primitives change only through `shadcn add`/`shadcn diff`" it quotes becomes "through `shadcn add`, plus the patches in the register"; `shadcn diff` is replaced by `shadcn add --dry-run --diff`. ADR-0007: `packages/ui` exports a Tailwind entry and a Tailwind-free theme stylesheet, and the theme bullet gains the `color-scheme` declaration and the root `TooltipProvider` and `Toaster`. ADR-0009: `sonner` enters the catalog under its existing approval; `motion` stays approved and uninstalled. The frontend rule "150–300 ms ease-out" is expressed by the motion tokens.

## Consequences

- A colour, a type role, a width or a duration changes in one file, and every page, primitive and composite follows; a later app or package reuses the theme without a second copy of Tailwind's base layer.
- A contrast regression fails `pnpm test:unit` instead of reaching a screen; a new colour needs a passing pair and, through the kitchen-sink spec, a swatch.
- Reduced motion applies to every animation and transition, including those inside generated primitives, without per-component work; a spinner is a still icon under the preference, so loading states are also announced.
- Refreshing a registered primitive is a deliberate act: the patch is re-applied from the register, and losing it fails `pnpm typecheck` (checkbox items, slider, sonner, the accordion's `headingLevel` wherever it is passed) or a Playwright assertion: `aria-valuenow` in the kitchen-sink and attachments specs (progress), and in the kitchen-sink spec the focus rings of the menu bar triggers and tab panels and the level-4 accordion headings. A patch that is not in the register is a review finding.
- A spacing or container name added to `tokens/layout.css`, an easing name added to `tokens/motion.css` or a type role added to `tokens/typography.css` without its `createCn` entry fails `pnpm test:unit`, and a role on a component's `className` fails `pnpm lint`.
- Visible changes on existing pages: darker input, checkbox, radio and switch borders, darker light-theme status colours (warning text is dark amber), a slightly darker light `primary`, a darker light and a lighter dark `destructive`, a 300 ms `fade-up`, the `ease-standard` transition curve, a 0.75rem eyebrow on the 404 and error pages, toasts in Geist Sans instead of the system font, keyboard focus that stops below the sticky header, and the chosen theme outlined in forced-colours mode.
- The kitchen-sink spec runs on every Playwright project in both themes, which adds run time to each end-to-end job; screenshots stay artefacts, not baselines.
- Revisit: the sidebar and command palette (`authentication-authenticated-application-shell`), the combobox, date pickers and forms (`web-foundation-forms-and-validation-kit`), the chart palette (`reporting-web-dashboards-and-reports`), and `global-error` and `motion` (`web-foundation-feedback-motion-and-accessibility-baseline`).
