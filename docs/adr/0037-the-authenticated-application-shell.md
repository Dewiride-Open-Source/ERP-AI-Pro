# ADR-0037: The authenticated application shell

Status: accepted
Date: 2026-10-09

## Context

- `authentication-authenticated-application-shell` asks for the `(app)` layout with a collapsible sidebar built from the typed navigation registry, a top bar with a Ctrl+K command palette, breadcrumbs, a user menu and the theme toggle, a drawer on phones and React `ViewTransition` route transitions, covered by the navigation crawl on desktop and mobile in light and dark.
- Until now the shell was a sticky header: the wordmark, the registry's entries as links hidden below `sm` (a phone had no navigation at all, only the start page's cards), the account area (the person's name and a Sign out button, ADR-0036) and the theme toggle. Every page entered through the CSS `PageTransition` rendered by `app/(app)/template.tsx` (ADR-0027).
- The shadcn `sidebar` primitive was excluded because its generated `use-mobile` hook sets state inside an effect, which `react-hooks/set-state-in-effect` refuses (ADR-0023); this item's roadmap note asks to install it with a hook on `useSyncExternalStore`, recorded in the patch register, and to export `./hooks/*`. Installing it beside the existing primitives, the CLI stops at its first "already exists" prompt and writes nothing when no one answers; the installed `button`, `input`, `separator`, `sheet`, `skeleton` and `tooltip` differ from the registry only in formatting.
- The shadcn `command` item needs `cmdk`, which is not approved. On 2026-10-09 cmdk 1.1.1 (MIT) had had no release since 2025-03-14, its repository no push since 2025-10-29, and its issue 413, an `aria-activedescendant` absent at mount and stale after filtering, was still open; these are the reasons the owner gave on 2026-09-27 for building the combobox in-house (ADR-0025). The owner decided on 2026-10-09 to build the command palette in-house as well.
- React 19.3.0 exports `ViewTransition` and `addTransitionType` as stable, and the App Router of Next.js 16.3.6 runs view transitions without configuration; `Link` has taken `transitionTypes` since 16.2.0 (the guide "View transitions" in `node_modules/next/dist/docs`). A `ViewTransition` runs its enter or exit animation only when it is the first component inserted or removed in a transition and is placed before any DOM node (react.dev, "ViewTransition"). A layout persists across navigations and a template remounts only when its child segment changes, so neither tells two pages of one segment apart, such as `/platform/system-info` and `/platform/attachments`.
- A layout renders again only on a full page load (ADR-0036), so whatever in the shell depends on the current page has to read it in the browser.
- Filtering the navigation by permission moved to `user-management-roles-and-permissions` (owner decision of 2026-09-29, ADR-0031). The registry's `NavigationEntry` carried an optional `permission` member that no code read.

## Decision

- **The registry.** `NavigationEntry` (`shared/layout/navigation-entry.ts`) is `{ id, title, description, basePath, featureFlag, area, icon }`: `area` (`{ id, title }`) is declared once per domain in `features/<domain>/_shared/<domain>-area.ts` (`platformArea`, "Platform") and named by each module's `nav.ts`, and `icon` is a `lucide-react` icon component, rendered on the server. The registry's order is the order of the areas and of their entries (`navigationAreas`). The unused `permission` member is removed. Two places filter the registry by feature flag, as before: `AppShell`, for the sidebar, the breadcrumbs and the page search, and `StartPage`, for the start page's cards; `user-management-roles-and-permissions` adds the permission filter in both.
- **The layout.** `AppShell` (server) reads the feature flags and the cookie `sidebar_state` and renders `SidebarProvider` (open unless the cookie says `false`, `sidebarStartsOpen`) around the skip link, `AppSidebar` and a column holding the sticky top bar (`h-header`, `px-gutter`, `z-(--layer-sticky)`), `main#main-content` (`max-w-page`, the skip link's target) and the footer. `SidebarInset` is not used, because it renders a `main`, and the top bar must not sit inside the region the skip link skips to. The cookie name is repeated in `shared/layout/navigation/sidebar-state.ts`: the primitive's constant lives in a client module, which hands a server component a reference instead of the string.
- **The sidebar.** `Sidebar collapsible="icon"`: its header holds the wordmark, a link home with a tooltip when collapsed, and, in the drawer only, "Close navigation", because the drawer hides the sheet's own close button; its content is `nav "Primary"` with Home and one labelled list per area. Each link is a `NavigationLink` (client), which reads the path with `usePathname`: `aria-current="page"` on the current page's link, `aria-current="true"` on an entry whose page is below it (`currentPage`). From `md` (48rem, 768 px at the browser's default font size) the sidebar collapses to icons through the top bar's "Navigation" button or Ctrl+B or Cmd+B, and the primitive writes the state to `sidebar_state` (seven days), so a reload keeps it; below `md` it is the primitive's `Sheet`, a dialog named "Navigation" (a register patch of the sheet's hidden title and description) opened by the same button. `MenuButton` exposes `aria-expanded`, and `aria-haspopup="dialog"` for the drawer, only once the page is hydrated, because the server cannot know which of the two is shown, and stays disabled with `data-hydrating` until then. `useIsMobile` asks `(width < 48rem)`, the breakpoint's own unit, so the hook and the `md:` classes switch together at any default font size; a pixel query left a window between them in which neither the sidebar nor the drawer showed. The drawer opens from state, not from a dialog trigger, so Radix would return focus to nothing when it closes, and the registry leaves it open over a page a link in it opened. Patches of `sidebar.tsx` in the register make it behave: the drawer's content records the focused element as it opens and, once it has closed (`onCloseAutoFocus`, after the content unmounts and the page outside it is no longer hidden with `aria-hidden`) and unless another layer took focus from the drawer, which then returns it itself (the page search opened over the closing drawer, both closing in the same frame), or another element holds focus by then, focuses that element again, or the Navigation button when it was the page body, is gone, or a link in the drawer was followed, because the new page replaces what the person was on; a plain click on any link in the drawer closes it, the wordmark's included, while a click that opens the link in another tab or window leaves it open for the next one; leaving the phone layout closes it, so a phone turned to landscape and back does not open it again by itself; and holding Ctrl/Cmd+B toggles once, because the primitive ignores the key's repeats.
- **The top bar.** The Navigation button; on phones the wordmark's mark, a link home (on desktop the sidebar shows the wordmark); the breadcrumbs from `lg` (1024 px), because between `md` and `lg` the expanded sidebar leaves the trail too little width and it would wrap out of the bar; then Search, the theme toggle and the user menu.
- **Breadcrumbs follow the registry** (`breadcrumbTrail`, `AppBreadcrumbs` reading `usePathname`): the start page is Home, current; a page under an entry is Home, the area (text: an area has no page of its own) and the entry, current on its own page and a link from a page below it; a page the registry does not reach (the `/design` harnesses, a not-found page) shows Home alone. A trail is never guessed from the address: a page below an entry that needs its own step, such as a record's name, adds it when such pages arrive.
- **The command palette is built in-house** (owner decision of 2026-10-09). `CommandPalette` (`packages/ui`, `components/command/`; contract in [design system](../architecture/design-system.md#command-palette)) is a modal dialog around a combobox and a listbox following the combobox pattern of WAI-ARIA APG: focus stays on the input, `aria-activedescendant` names the active option, every word typed must appear in an item's label, description, group or keywords (`filterCommands` over `searchText`, which moves from the combobox to `lib/search/search-text.ts` so both share it), and the arrow keys wrap. A pointer at rest never takes the active option from the keyboard (`followPointer`, shared with the combobox), because WebKit raises `mousemove` at a resting pointer whenever the list scrolls under it. The shell's `PageSearch` (client) opens it from the Search button or on Ctrl+K or Cmd+K (`isPageSearchShortcut`: K with Control or Meta and neither Alt nor Shift, both modifiers on every platform; a held key keeps the browser's own Ctrl+K away and toggles the palette only on its first press), lists Home and every enabled entry with its description in its area's group, and opens the chosen page with `router.push`. Only one of the drawer and the palette is open at a time: opening the palette closes the drawer, and while the palette is open a capture-phase listener holds back Ctrl/Cmd+B (`isNavigationShortcut`, exactly the key the primitive listens for, repeats included), so the sidebar's own listener never hears it; a held Ctrl+K opens or closes it once. The input row ends with a Close button that shows the Esc keycap, the way out on a touch screen without an Escape key, kept out of the Tab order so that Tab never takes focus off the search while an option is marked active; a press anywhere else in the dialog but the input keeps focus in the search; the dialog is never taller than the screen, and the list scrolls in the height left; and the active option has a 2px outline in `--ring`, which a background tint alone would not make visible enough (WCAG 2.2 SC 1.4.11). The palette opens from state, so it returns focus itself, once its content has unmounted, unless another layer took focus from it or anything but the page body holds focus by then: after a choice to the Search button (`returnFocusTo`), because the new page removes whatever the person was on; dismissed, to the element focused before it opened, or to the Search button when that was the page body or an element around the button, as after a click in WebKit, which focuses not the button it clicks but its nearest focusable ancestor, if there is one. The button shows the shortcut as "⌘K" on an Apple user agent and "Ctrl K" elsewhere (`pageSearchShortcutLabel`), read with `useSyncExternalStore`, so it renders differently once hydrated and carries `data-hydrating` until then.
- **The user menu** (`UserMenu`, `features/identity/auth/account`): the trigger shows the person's initials (`personInitials`, worked out on the server by `AccountArea`, because the grapheme rules of `Intl.Segmenter` follow the engine's Unicode version, so a browser could split a conjunct differently from the server and the menu would not hydrate) and from `md` the name, and is named "Signed in as <name>", or "Account" when the session could not be read; the menu, named "Account" (Chrome would otherwise name it after the trigger's whole content, the hidden initials included), shows the name, the user name and Sign out. The menu is non-modal (`modal={false}`), so opening it leaves the page's scrollbar and layout as they are, as do the data table's Columns menu and options filter; a modal menu locked the page's scrolling, which removed the scrollbar while the menu was open and made the page shake as it opened. The sign-out form stays outside the menu, because the menu unmounts its items as it closes and a removed form cannot be sent: the item calls the form's `requestSubmit`, so the submit handler of `useSignOutForm` (shared with the `SignOutButton` of the idle warning and of the ended-session dialog) fills `__RequestVerificationToken` as before (ADR-0033, ADR-0036). While the sign-out is under way the trigger is busy and the menu stays shut. `AccountArea` renders it with `SessionKeeper` on every page.
- **Pages change with a view transition.** `AppPage` (client, rendered by the template) keys `PageTransition` by the page's path, so a navigation to another path removes one boundary and inserts another in the same transition; `PageTransition` is a `ViewTransition` with `enter="page-enter"`, `exit="page-exit"` and `default="none"`, so a change of query (a list page), a refresh and a Suspense reveal update it in place and animate nothing. `tokens/motion.css` animates `::view-transition-new(.page-enter)` (from opacity 0 and 4px lower, `--motion-duration-normal`, `--motion-ease-enter`) and `::view-transition-old(.page-exit)` (to opacity 0, `--motion-duration-fast`, `--motion-ease-standard`), leaves `::view-transition-old(root)` and `::view-transition-new(root)` unanimated, so the sidebar and the top bar stay still, and lets `::view-transition` pass pointer events to the live page. The tokens collapse to 0.01 ms under reduced motion, and the reduced-motion safety net covers the view transition's pseudo-elements. A first load runs no transition. The CSS entrance and its `animate-page-enter` utility are removed.
- **The kitchen sink** shows a static sidebar (`collapsible="none"`) in its navigation section and the command palette with example commands in its composites section; the excluded table drops `sidebar` and records the decision on `command`.
- **Playwright.** The navigation spec covers the sidebar, its collapse and kept state, the drawer, the breadcrumbs and the user menu; a command palette spec drives the palette on every project; the navigation crawl visits every registry entry by clicking it in the sidebar, or in the drawer on a phone; the sign-out specs sign out through the user menu; the feedback spec observes the view transition of a client navigation, and its animated list compares against `--motion-duration-normal`. In WebKit running on Windows the `context` fixture removes the View Transitions API (a WebKit reached through `PW_TEST_CONNECT_WS_ENDPOINT` runs on the Linux server and keeps it): Playwright's WebKit port there crashed or hung in 8 of 15 client navigations that ran a view transition and in none without, while Linux WebKit ran all 15 both ways, so the transitions keep their coverage in CI's Linux WebKit and nothing else is left out on that project.
- **Earlier decisions this changes.**
  - ADR-0023: the `sidebar` primitive is installed, with its `use-mobile` hook on `useSyncExternalStore` in rem, and its sheet's title and description, the drawer's focus return, link closing and layout reset, and the shortcut's repeats in the patch register; `@dewiride/erp-ui` exports `./hooks/*`.
  - ADR-0027: pages no longer enter with the CSS `PageTransition`; a navigation runs a view transition, and `PageTransition({ transitionKey, children })` is that boundary.
  - ADR-0028: the navigation crawl clicks the registry's entries in the sidebar or the drawer instead of reading hidden header links.
  - ADR-0036: the user menu replaces the account area's name and Sign out button; the wordmark leads home from the sidebar, and from the top bar on phones.

## Consequences

- A phone has navigation: the drawer holds every entry the sidebar holds.
- The cookie `sidebar_state` is written by script, so it is neither HttpOnly nor `__Host-` prefixed; it holds only whether the sidebar is open, nothing personal, and the API never reads it.
- While the page has focus, Ctrl+K and Ctrl+B are the ERP's: they replace the browser's own shortcuts (in Chrome and Edge, Ctrl+K searches from the address bar; in Firefox, Ctrl+K searches the web and Ctrl+B shows the bookmarks), as in other web applications that offer a command palette. The buttons name both shortcuts in `aria-keyshortcuts`.
- A browser without the View Transitions API, or without its transition types, changes pages at once; Safari may animate differently. Nothing depends on the animation.
- Pages outside the registry show only Home in the breadcrumbs until such pages bring titles of their own.
- `user-management-roles-and-permissions` adds the read-permission filter where the feature-flag filter runs: in `AppShell` (the sidebar, the breadcrumbs and the page search) and in `StartPage`.
