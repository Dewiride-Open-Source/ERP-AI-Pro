# ADR-0027: Feedback, motion and the accessibility baseline

Status: accepted
Date: 2026-09-29

## Context

The `web-foundation-feedback-motion-and-accessibility-baseline` sub-phase asks for toasts, confirm dialogs, empty and error states with retry, skeleton loading states, optimistic-update helpers, page transition and list animation patterns that honour `prefers-reduced-motion`, and an accessibility baseline enforced by an axe scan in Playwright that fails on serious violations. Facts that shape the decision (web paths relative to `frontend/apps/web/src/`):

- **What exists.** ADR-0023 mounts one `Toaster` (sonner) and one `TooltipProvider` in the root layout and keeps the motion tokens and the reduced-motion safety net in `packages/ui/src/styles/tokens/motion.css`; ADR-0024 left the `(app)`-level `error.tsx` and `loading.tsx` and the theme of `app/global-error.tsx` open; ADR-0026 reads every list on the server with its view in the address, and every change is a Server Function.
- **Next.js 16.3.6.** `refresh()` from `next/cache`, called in a Server Action, refreshes the client router in the same response. A `loading.tsx` wraps its segment's children in a Suspense boundary keyed by the child segment: its fallback shows on a direct visit and when a navigation enters a new child segment, while a navigation between pages below the same child segment runs as a transition that keeps the old page on screen. Every page is rendered per request (the nonce content security policy), so no loading boundary is prefetched, and the server streams the fallback ahead of the page, which React's inline script swaps in. A `template.tsx` remounts when its segment changes, not when only the search parameters do.
- **React 19.3.** `useOptimistic(value, reducer)` shows the optimistic value only while its Action is pending; when the Action ends the passed value, including one the parent updated meanwhile, is shown again. The setter must run inside a transition or Action.
- **Motion 13.4.4** (`motion/react`, approved in ADR-0009): `MotionConfig reducedMotion="user"` turns off transform and layout animations under the preference but keeps opacity (and any other value); `LazyMotion` with `domAnimation` and the `m` components load only the animation features used; `AnimatePresence initial={false}` renders the children present at mount at their `animate` values, so server-rendered items are not hidden before scripts run.
- **axe.** Playwright's accessibility-testing guide uses `@axe-core/playwright` (`AxeBuilder` with `withTags`, `include` and `exclude` taking CSS selectors only, and `analyze`). axe-core 4.13.0 defines the tags `wcag2a` (62 rules), `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`. The owner approved `@axe-core/playwright` and `axe-core` (Deque Systems, MPL-2.0) for the end-to-end suite on 2026-09-29; Microsoft ships no Playwright accessibility package, and Accessibility Insights embeds the same axe-core.

## Decision

- **Packages.** `motion` 13.4.4 is a dependency of `@dewiride/erp-ui` only; its transitive `framer-motion` 13.4.4, `motion-dom` 13.4.4 and `motion-utils` 13.3.0 (MIT, the motiondivision organisation) are approved with it and declared nowhere; `tslib` (0BSD, Microsoft) was already present. `@axe-core/playwright` 4.13.0 is a dev dependency of `@dewiride/erp-e2e` only; `axe-core` 4.13.0 was already in the lockfile through `eslint-plugin-jsx-a11y`. The Dependabot `ui` group gains `motion` and the `playwright` group `@axe-core/*`. The GitHub Advisory Database and `pnpm audit --prod` listed nothing for them on 2026-09-29.
- **Composites** (`packages/ui/src/components/`, contract in `docs/architecture/design-system.md`, section "Feedback"):
  - `feedback/confirm-dialog.tsx`: `ConfirmDialog({ trigger, title, description, confirmLabel, cancelLabel = "Cancel", tone, onConfirm, focusAfterConfirm })` over the generated alert dialog. Radix focuses Cancel when it opens and returns focus to the trigger when it is cancelled; after a confirmation `focusAfterConfirm()` receives focus instead, because the confirmed action often removes the trigger.
  - `feedback/error-state.tsx`: `ErrorState({ title, description, reference, onRetry, retryLabel = "Try again", headingLevel, focusOnMount, className })`: an icon, an `h1` or `h2` that can take focus (`tabIndex={-1}`), the description, "Reference: <value>" and a retry button that runs `onRetry` in a transition and stays focusable while busy (`aria-disabled`, `aria-busy`, a spinner).
  - `feedback/loading-status.tsx`: `LoadingStatus({ label, ...div })`: `role="status"` named by `aria-label`, with the same words in a visually hidden span, around a skeleton. Every loading skeleton uses it.
  - `layout/skip-link.tsx`: `SkipLink({ targetId, label = "Skip to main content" })`, visually hidden until it receives focus.
  - `motion/page-transition.tsx`: `PageTransition`, a `div` with `animate-page-enter` (`page-enter var(--motion-duration-normal) var(--motion-ease-enter) backwards`: from opacity 0 and 4px lower). It is CSS, so a page shows before its scripts run, and the `backwards` fill leaves no transform once it ends, because a transformed ancestor would become the containing block of every fixed-position descendant.
  - `motion/animated-list.tsx`: `AnimatedList` (a `ul` with `role="list"` inside `LazyMotion features={domAnimation} strict`, `MotionConfig reducedMotion="user"` and `AnimatePresence initial={false}`) and `AnimatedListItem` (`m.li` growing from height 0 and opacity 0, shrinking out the same way, clipped only while its height changes so focus rings inside it show once it settles). Its timing comes from the tokens: `use-motion-timing.ts` reads `--motion-duration-normal` and `--motion-ease-enter` from the document with `useSyncExternalStore`, re-read when the reduced-motion preference changes, and `motion-tokens.ts` parses them (`durationInSeconds`, `cubicBezier`, `motionTiming`, unit-tested). The tokens collapse to 0.01ms under the preference, so the JavaScript animations follow the same rule as the CSS ones.
  - `theme/use-stored-theme.tsx`: `useStoredTheme()` resolves the theme the person chose (`localStorage` key `theme`, the `storageKey` `ThemeProvider` now passes explicitly from `theme/stored-theme.ts`) or else the system preference, with `light` on the server.
  - The generated `ui/table.tsx` makes its scroll container focusable while the table is wider than it (the register in `design-system.md`).
- **Toasts** report the outcome of an action whose visible trace changed or disappeared: a file deleted, a request dismissed, a quotation archived. An error a person must act on stays next to its control. A refused removal is reported in an error toast, because the row whose control would show it was taken off the list while the Server Function ran and comes back without that state.
- **Optimistic removal** (`shared/lists/`). `ListTable` keeps `{ page, rows }` in `useOptimistic` with `withoutRow` (`optimistic-rows.ts`: the row leaves, `totalCount` drops by one and `pageCount` is recomputed). A row's control calls `useRemoveRow()` (`list-row-removal.tsx`) and then `removeRow(id, remove)`, which hides the row inside a transition and awaits `remove`, a Server Function answering `RowRemovalOutcome`; `settleRemoval` turns a rejected call into the form kit's messages (`rejectedActionState`, after `unstable_rethrow`), and a removed id leaves the selection. The Server Function calls `refresh()`, so the refreshed rows arrive in its answer and the row never flickers back; when it refuses without refreshing, the optimistic state ends and the row returns. The attachments delete uses it and refreshes after the API answers either way, so a file another tab already deleted stays off the list while its error toast explains why.
- **Error boundaries.** `(app)/error.tsx` renders `ErrorPage` inside the shell and the root `error.tsx` the full-screen `ErrorPage` (`shared/layout/error-page.tsx`): an `ErrorState` whose `h1` takes focus, with the digest as its reference and the boundary's `retry` as Try again. `global-error.tsx` renders `ApplicationFailure` in the stored theme: it replaces the root layout and runs without `ThemeProvider`, whose script it could not give a nonce.
- **Loading.** `(app)/loading.tsx` renders `PageLoading` ("Loading the page"). It shows on a direct visit and on entering a new section for a page without a loading file of its own. A page that takes noticeable time to prepare therefore owns a `loading.tsx` whose skeleton follows its own layout, which is what a navigation within its section shows.
- **Page entrances.** `(app)/template.tsx` renders `AppPage` (`shared/layout/app-page.tsx`), which wraps the page in `PageTransition`; the page components drop their own `animate-fade-up`, which the sign-in card keeps outside the shell.
- **Accessibility baseline.** `AppShell` renders `SkipLink` before its header and gives `main` `id="main-content"` and `tabIndex={-1}`. The Playwright `capture(name, target?)` fixture scans every captured screen before its screenshot: it waits for every finite animation to finish (contrast is measured on what is painted), runs `AxeBuilder` with `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`, limited to the captured element when there is one, and fails the test on a `serious` or `critical` violation. It excludes `[data-aria-hidden='true']`, the content Radix hides behind an open modal layer while trapping focus inside the layer (scanned again in the captures without it), and the aria-hidden focus proxy an open Radix navigation menu renders beside its trigger. The first scans found, and this change fixes, a disabled slider field without `aria-disabled` and a recent-starts table that scrolled sideways on phones without being reachable from the keyboard.
- **Harness.** `/design/feedback` (`features/platform/design/feedback`) shows each pattern: ConfirmDialog, a server-driven approvals list whose dismissals the Server Function keeps in an `HttpOnly` cookie scoped to the page (one request is locked and refused), reminders in an `AnimatedList` with one validation failure, an `ErrorState` that recovers, a button that makes the page throw, and links to other pages. `/design/feedback/report` takes three seconds to prepare and owns a `loading.tsx`.

## Consequences

- Every page in the shell streams: the server sends a loading status ahead of the page and React's inline script swaps the page in, so the ERP needs JavaScript to show its pages (the pages with their own loading file already did). The form kit's "before the page is interactive" test aborts the app's script files instead of turning JavaScript off.
- Moderate and minor axe findings are not enforced; the capture's scan adds a fraction of a second, and a whole-page capture of the kitchen sink up to about a second.
- The axe exclusions are selectors in `frontend/e2e/fixtures/test.ts`, each explained there; a new exclusion is a change to this ADR.
- **Earlier decisions this changes.** ADR-0023: `motion` is installed and used by `AnimatedList` only; pages enter through `animate-page-enter` in the shell. ADR-0024: the `(app)` segment gains `error.tsx`, `loading.tsx` and `template.tsx`, and `global-error.tsx` follows the stored theme. ADR-0026: `ListTable` owns optimistic removal.
