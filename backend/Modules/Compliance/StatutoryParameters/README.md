# Compliance / StatutoryParameters

The government rates, codes, due dates and limits the ERP uses, each set dated by the instruments that brought its versions ([ADR-0063](../../../../docs/adr/0063-statutory-parameters-dated-rows-in-versioned-sets-typed-reads-by-date-and-the-first-gst-datasets.md)). A set changes only with a release: its seed file changes with each notification and the seeder follows it, so no route records, corrects or removes a parameter.

| Aspect | Value |
|---|---|
| Assembly | `Dewiride.Erp.Modules.Compliance.StatutoryParameters` |
| Schema | `compliance_statutory_parameters` (`StatutoryParametersDbContext`): `ParameterSets` (the key, unique, the title, description, basis, as-of rule and the declared columns as a `json` value), `ParameterVersions` (the date a version applies from and its instruments, unique by set and date) and `ParameterRows` (a row's key, the dates it is in force, its cells as canonical text in a `json` object and its source, unique by set, key and start, indexed by set and dates); all three audited, their foreign keys `Restrict` |
| Seed files | `ParameterSets/Persistence/Statutory/<area>/<key>.json`, embedded as `statutory/<key>.json` and read strictly (`StatutorySeedFiles`): a member the shape does not know, a member written twice, a number in quotes, a value that breaks its column's kind or range, a row that starts or ends off a version's boundary, rows of one key that overlap, a version that changes nothing, a version of a set dated by financial year that does not start on 1 April, a code a column references or a GST State code (`IIndianStates` of `Platform/ReferenceData`) that is not in force on every day of its row. The checks run in stages, and a stage runs only on what the stages before it passed: the shape of each file and its set's definition (key, basis, as-of rule and columns), then each version and each row with its cells, then the date rules, then the references and GST State codes across the files; so a defect of an earlier stage can hide one of a later stage until it is fixed, and every defect a stage finds in any file is reported together |
| Seeding | `StatutoryParameterSeeder` (order 200, after the reference data's 100 and 110) makes the tables equal to the files: a set is known by its key, a version by its set and date and a row by its set, key and start; a missing one is added, the rest follows its file and one no file holds is deleted, each change recorded by the system in one save. A defective file stops the seeder, and with it the migrator, before the seeder writes anything; the migrations and the seeders ordered before it stay applied. A legal change is a new version; a correction of the ERP's copy edits a row and shows only in the audit trail |
