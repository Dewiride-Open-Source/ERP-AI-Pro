# Platform / Audit

HTTP surface of the change history (`BuildingBlocks/Auditing`, `IChangeHistory`): list and export the changes the persistence building block records for every recorded type, in the same save as each change ([ADR-0043](../../../../docs/adr/0043-change-records-and-the-append-only-audit-schema.md)). The recording, the table and the reading live in the building blocks, so that recording never depends on this module or its flag; this module adds the routes, the handlers and the CSV export.

| Aspect | Value |
|---|---|
| Assembly | `Dewiride.Erp.Modules.Platform.Audit` |
| Schema | none of its own; the auditing building block owns `audit` (`AuditingDbContext`: `ChangeRecords`, `SecurityEvents`) |
| Route group | `/api/platform/audit`: `GET /changes` (paged: `page`, `pageSize`, `sort` on `occurredAt` only, newest first by default with the id breaking ties, `filter` on `entityType`, `entityId`, `subjectType`, `subjectId`, `actorId`, `operation` and `correlationId` with `eq`, `ne` and `in`, and on `occurredAt` also with `gt`, `gte`, `lt` and `lte`), `GET /changes/export?filter=` (the public request record `ExportChangesRequest`: `filter`, optional, in the grammar and over the fields of the list) |
| Feature flag | `Erp.Modules.Platform.Audit`; it gates the reading only, and every change is recorded while it is off |
| Permissions | `platform.audit.changes.read` (`GET /changes`) and `platform.audit.changes.export` (`GET /changes/export`), Administrator's alone (declared in `AuditPermissions`, [ADR-0041](../../../../docs/adr/0041-roles-and-permissions.md)); anyone else answers 403 `request.forbidden` |
| Answers | a change is `ChangeRecordResponse`: the operation (`created`, `updated`, `deleted`, `restored`), the changed record and the record it is filed under by their change keys and ids with the subject's name, the actor (`actorKind` `person`, `system` or `anonymous`, the Entra object id and the name the person's record has today), the client address, the correlation id and the changed values (`ChangedValueResponse`: the field's camelCase path, its `kind`, the values before and after as text, and for a reference the change key it refers to with the names of both records) |
| Export | `text/csv; charset=utf-8` written by `ChangeCsvWriter` into `TypedResults.Stream` while the history is read oldest first, flushed after every 500 records: RFC 4180, every cell quoted, UTF-8 with a byte order mark, one line per changed value and one for a record without values, and a cell that would begin a formula starts with an apostrophe (`CsvCells`); `Content-Disposition: attachment` named `change-history-<yyyyMMdd-HHmmss in IST>.csv` after the moment the export started; at most 100,000 lines, refused before the first byte with 422 `audit.export-too-large`; a request timeout of five minutes; the rate-limiter policy `platform.audit.exports`, two exports for the whole process and no queue, over which it answers 429 `rate-limit.exceeded` with `Retry-After` |
| Security events | the export is the command `ExportChangesCommand`, which records `ChangeHistoryExported` (detail `records:<number of records exported>`, the administrator's object id, the client address and the correlation id) before the first line; an export whose event cannot be written answers 500 without the file, and a refused export records nothing |
| Names | resolved when the history is read, never stored: subjects and references through every registered `IRecordNames` (`UserRecordNames` of `Identity/Users`, `AttachmentRecordNames` of `BuildingBlocks/Attachments`), actors through `IPersonNames` (`UserRecordNames`) |
| Contract | `AuditPermissions` |
| Events | none |
