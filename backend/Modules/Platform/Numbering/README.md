# Platform / Numbering

HTTP surface of the document numbering building block (`BuildingBlocks/Numbering`, `INumberingAdministration`): list the kinds of document the ERP numbers with the rule their numbers follow and their numbering, set a numbering up and change it ([ADR-0066](../../../../docs/adr/0066-document-numbering-series-per-kind-of-document-fixed-for-a-year-at-its-first-number-and-taken-in-the-issuing-transaction.md)). The kinds, the tables and the numbers live in the building block, so that a module numbers its documents with `IDocumentNumbers` without referencing this module and whatever this module's flag says; this module adds the routes, their handlers and `ISerialNumberRules`, which answers the rule of a kind of document from the statutory parameter set `gst.document-serial-numbers`.

| Aspect | Value |
|---|---|
| Assembly | `Dewiride.Erp.Modules.Platform.Numbering` |
| Schema | none of its own; the building block owns `platform_numbering` (`NumberingDbContext`: `NumberSeries`, `NumberSeriesYears`) |
| Route group | `/api/platform/numbering`: `GET /documents` (every kind of document this release declares, by title, with the rule of the current financial year, null when the ERP holds none, and its numbering, null until it is set up), `GET /series/{id}`, `POST /series` (idempotency key) and `PUT /series/{id}` (with the version the change was made from) |
| Feature flag | `Erp.Modules.Platform.Numbering`; it gates the routes only, and a module still numbers its documents while it is off |
| Permissions | `platform.numbering.series.read` (both `GET` routes) and `platform.numbering.series.change` (`POST /series`, `PUT /series/{id}`), held by Finance and administrators (declared in `NumberingPermissions`, [ADR-0041](../../../../docs/adr/0041-roles-and-permissions.md)); anyone else answers 403 `request.forbidden` |
| Answers | `NumberedDocumentResponse` (key, title, description, the current financial year, `SerialNumberRuleResponse`: the most characters and the characters besides letters and digits, and `NumberSeriesResponse`: id, the format the next year to open takes, version and the years opened, the latest first); a year is `NumberSeriesYearResponse` (the year, its format, the length its rule allowed, its first, next and last running numbers, whether it has given a number, and its first, next, last and last given numbers as text); a format is `NumberFormatResponse` (prefix, `year` `none`, `full` or `abbreviated`, separator, digits) |
| Set up | `POST /series` opens the current financial year at the next number asked; a kind no release declares answers 400 `numbering.document-unknown`, one already set up 409 `numbering.already-set-up`, a year without a rule 422 `numbering.no-rule`, a format the year's rule refuses 400 `numbering.format-invalid` with the field at fault (`format.prefix`, `format.year`, `format.separator`, `format.digits` or `format`), and a next number outside 1 to the last that fits 400 `numbering.next-number-out-of-range` |
| Change | `PUT /series/{id}` gives the current year the new format and next number while it has given no number; a year that has given one keeps its format and next number, the format applies from the next year, and a different next number answers 400 `numbering.year-in-use`; an outdated version answers 409 `concurrency.conflict`, a malformed one 400 `numbering.version-invalid`, and an id no numbering has 404 `numbering.series-not-found` |
| Contract | `NumberingPermissions` |
| Events | none |

A numbering is changed only through the building block's administration, which runs each change in a unit of work of its own on `NumberingDbContext` and takes the lock a number takes, so the module owns no context and its commands run without a unit of work.
